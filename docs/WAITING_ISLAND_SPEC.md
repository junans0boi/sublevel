# 대기 섬 스펙 (매칭 후 카운트다운 대기 공간)

상태: 기획 확정(준환 승인 2026-11-18). 구현은 봇 B5~B8·동기화 종료 후. 게임 룰 변경 아님 → ADR 불필요(필요해지면 ADR-330~339 대역).
이슈: 스펙 이슈·지도 이슈·티켓은 GitHub(`junans0boi/sublevel`)에 있다(번호는 `docs/PROGRESS.md` 또는 지도 이슈 참조).

## Problem Statement
매칭이 잡힌 뒤 판이 시작되기까지(최대 90초) 플레이어는 지금 아무 공간도 없이 대기 화면만 본다. 인원이 차는 과정이 보이지 않아 "이 게임에 사람이 있는지" 느낄 수 없고, 기다리는 동안 할 일이 없다. 메인 메뉴 3D 엘리베이터 로비는 매칭 전(장비·캐릭터·파티)용이라 이 역할을 맡기 어렵다.

## Solution
매칭 후 플레이어는 같은 월드 안 플레이 범위 밖 먼 바다의 **밀폐된 승강장 섬**(지름 약 80m, 지하 승강장 겸 놀이동산 분위기: 철골·돔·번지 타워·사격장 부스·큰 전광판)에 모인다. 걸어 다니며 번지점프를 하고(1차), 사격장·전광판 순위를 즐기며(2차) 카운트다운을 기다린다. 봇도 섬에 모여 인원이 늘어나는 것처럼 보인다. 카운트다운이 끝나거나 인원이 차면 서버가 모두를 기존 승강장 투입 흐름(60슬롯 배정)으로 승강기에 태워 판을 시작한다. 섬에서의 어떤 것도 본 판에 영향을 주지 않는다.

## 확정된 결정 (준환 승인)
1. 위치: 같은 월드 안, 플레이 범위 밖 먼 바다. 밀폐 승강장 섬(지름 ≈80m). 바깥은 바다+안개로 본 맵에서 안 보임. float 정밀도 안전 거리 안.
2. 접근: 대기자는 서버 권위로 섬 경계 안으로만 이동(클램프). 판 시작 시 엘리베이터 칸으로 텔레포트(기존 슬롯 배정·투입 재사용). 봇도 섬에 모여 사람처럼 보임(처음 소수→점차 증가, 걷기·서성이기·사격장 이용 수준). 현황판 인원 = 사람+봇 합계. **'봇을 사람처럼 보이게'는 RISKS_OPEN_QUESTIONS.md에 사람 검토 항목으로 올림.**
3. 카운트다운: 최대 90초, 인원 가득이면 15초로 단축, 끝나면 부족분을 봇으로 채움. 시작점은 현 `--start-seconds 60`, 값은 `MatchRules` 설정화.
4. 메인 메뉴 3D 엘리베이터 로비 유지(매칭 전). 대기 섬은 매칭 후 전용.
5. 콘텐츠: 1차 번지점프(전광판=카운트다운·인원·번지 최고 높이) → 2차 전광판 확장(번지/사격 TOP3·지역 안내·팁 순환, 기록은 대기 안에서만) + 사격장(TrainingDummy 재활용) → 3차 자동차 경주(별도 지도 티켓으로만).
6. 번지: 줄 물리 없음. 서버가 낙하-반동 곡선으로 위치를 구동하는 연출형. 사망·피해 없음. 한 번에 한 명, 짧은 쿨다운, 카메라 흔들림·가속 연출, 반동 높이 기록.
7. 대기 섬에서 사람·봇 간 모든 공격(주먹·총격) 차단(피해 0). 사격은 사격장 부스 안 표적에만(부스 대여 총). 본 판 장비는 섬에서 꺼낼 수 없음. 본 판으로 이월 없음(아이템·탄약·능력치 없음; 꾸미기·칭호는 나중).
8. 착수 시점: 봇 B5~B8(#374~377)·동기화(#397·#398) 종료 후 매칭(#392)·서버 로비와 묶어 진행. Unity 작업은 한 번에 하나(티켓 직렬).

## 가정(DECISIONS 기록 후보, 질문하지 않고 진행)
- 섬 위치는 월드 중심에서 float 안전 범위(대략 ≤ 5 km) 안, 맵 가장자리 바다 밖 방향. 정확한 좌표는 첫 구현 티켓에서 월드 경계·안개 거리로 정한다.
- 이 변경은 룰이 아니다: 섬 상태는 매칭 파이프라인의 앞 단계이며, 판 규칙(SPEC)·승강장 배정 규칙은 그대로다. 구현 중 룰 변경으로 판명되면 ADR(330~339) 선행.
- 카운트다운 값(90/15/봇 채움 시점)은 `MatchRules` 데이터. 기존 `QueueWindowSeconds(30)`·`--start-seconds`와의 관계는 T1에서 정리(대체하거나 매핑).
- 번지 기록은 섬 세션 메모리에만(서버 저장은 범위 밖).

## User Stories
1. 매칭된 플레이어로서, 기다리는 동안 걸어 다닐 수 있는 공간을 원한다, 그래야 대기가 지루하지 않다.
2. 플레이어로서, 큰 전광판에서 남은 시간을 보고 싶다, 그래야 언제 시작할지 안다.
3. 플레이어로서, 현황판에서 모인 인원(사람+봇)을 보고 싶다, 그래야 판이 곧 찰지 가늠한다.
4. 플레이어로서, 번지 타워에서 뛰어내려 보고 싶다, 그래야 대기 시간을 재밌게 쓴다.
5. 플레이어로서, 번지 반동 높이가 전광판에 최고 기록으로 뜨길 원한다, 그래야 서로 겨룬다.
6. 플레이어로서, 번지는 한 번에 한 명만 뛰고 짧은 쿨다운이 있길 원한다, 그래야 연출이 겹치지 않는다.
7. 플레이어로서, 번지에서 죽거나 다치지 않길 원한다, 그래야 마음 놓고 즐긴다.
8. 플레이어로서, 낙하 때 카메라 흔들림·가속감을 느끼고 싶다, 그래야 짜릿하다.
9. 플레이어로서, 섬 경계 밖으로 나갈 수 없길 원한다, 그래야 길을 잃지 않는다.
10. 플레이어로서, 인원이 가득 차면 카운트다운이 15초로 줄길 원한다, 그래야 오래 기다리지 않는다.
11. 플레이어로서, 시간이 끝나면 부족한 자리가 봇으로 채워져 판이 시작되길 원한다, 그래야 항상 판이 돈다.
12. 플레이어로서, 판 시작 때 내 승강기 칸으로 자동 이동하길 원한다, 그래야 기존 투입 흐름 그대로 경기를 시작한다.
13. 플레이어로서, 팀원과 같은 승강기 칸에 배정되길 원한다, 그래야 파티 플레이가 유지된다.
14. 플레이어로서, 섬에서 다른 사람·봇을 때리거나 쏴도 피해가 없길 원한다, 그래야 장난·공격 걱정이 없다.
15. 플레이어로서, 사격장 부스에서 빌린 총으로 표적을 쏘고 싶다(2차), 그래야 사격 감각을 예열한다.
16. 플레이어로서, 본 판 장비를 섬에서 꺼내지 못하길 원한다, 그래야 섬이 판에 영향을 주지 않는다.
17. 플레이어로서, 섬에서 얻은 것이 본 판으로 이월되지 않길 원한다, 그래야 공정하다.
18. 플레이어로서, 처음엔 사람이 적고 시간이 갈수록 늘어나는 모습을 보고 싶다, 그래야 실제 매칭처럼 느껴진다.
19. 플레이어로서, 다른 인원이 걷고 서성이고 사격장을 이용하는 걸 보고 싶다, 그래야 섬이 살아 있다.
20. 플레이어로서, 전광판에서 번지/사격 TOP3·지역 안내·팁을 순환으로 보고 싶다(2차), 그래야 대기 중 정보를 얻는다.
21. 플레이어로서, 바깥은 바다·안개뿐이고 본 맵이 보이지 않길 원한다, 그래야 몰입이 깨지지 않고 정보가 새지 않는다.
22. 플레이어로서, 메인 메뉴의 3D 엘리베이터 로비가 그대로이길 원한다, 그래야 장비·캐릭터·파티 준비는 같은 곳에서 한다.
23. 플레이어로서, 대기 중 접속이 끊겼다 돌아와도 섬에 다시 들어가길 원한다, 그래야 억울하지 않다.
24. 개발자로서, 카운트다운·봇 채움 값을 `MatchRules` 데이터로 바꾸고 싶다, 그래야 코드 수정 없이 조율한다.
25. 개발자로서, 대기 중 이동·번지·표적 사격이 모두 서버 권위이길 원한다, 그래야 클라이언트 조작으로 속일 수 없다.
26. 개발자로서, 섬 장면이 PERF 예산 안에 들길 원한다, 그래야 본 판 성능에 영향이 없다.
27. 개발자로서, 섬 규칙(카운트다운·클램프·번지 곡선·사격 허용 판정)이 순수 함수라 헤드리스 테스트되길 원한다, 그래야 Unity 없이 빨리 검증한다.
28. 운영자로서, 서버 로그에 대기 인원·카운트다운·시작 사유(가득/시간 종료)가 남길 원한다, 그래야 문제 추적이 된다.
29. 준환으로서, 봇을 사람처럼 보이게 하는 부분이 사람 검토 항목으로 올라 있길 원한다, 그래야 출시 전 판단한다.

## Implementation Decisions
- **상태 모델**: 매칭이 확정된 참가자는 판 시작 전까지 '대기 상태'. 서버의 `MatchDirector`/매칭 흐름에 대기→투입(기존 `Deployment` 60슬롯 배정·`ElevatorRides`)→판 진행 순서를 추가한다. 투입 흐름 자체는 바꾸지 않고 텔레포트 출발지만 섬이 된다.
- **카운트다운 규칙은 순수 함수**(Core): 입력 = 경과 시간·사람+봇 인원·참가 상한, 출력 = 남은 시간·시작 사유. 최대 90초, 가득이면 15초로 단축(남은 시간이 15초보다 길 때만), 끝나면 `BotFill`로 부족분 채움. 값은 `MatchRules` 데이터(JSON) — `--start-seconds 60`은 시작점/호환 인자.
- **섬 지오메트리**: 월드 씬 안 먼 바다의 별도 구조물(지름≈80m, 돔·철골·번지 타워·사격장 부스·전광판). 밀폐(바깥 바다·안개는 본 맵 비가시), 본 맵 카메라·미니맵·구역 시스템과 분리. 플레이 범위 밖이라 오염·구역·루팅 시스템 비적용.
- **이동 클램프**: 서버가 대기자 위치를 섬 경계 원/다각형 안으로 보정(서버 권위, 클라 예측 보정 포함).
- **전투 차단**: 대기 상태 Combatant는 피해 입력 0(주먹·총·투척·차량), 발사·근접 행동 비활성. 사격장 부스 안에서만 대여 총 사용 가능(2차), 표적은 `TrainingDummy` 재활용, 본 판 장비·인벤토리는 대기 중 접근 불가·이월 없음.
- **봇 대기 행동**: 대기 봇은 판 AI(파밍·교전)를 쓰지 않고 단순 행동(걷기·서성이기·사격장 이용)만. 합류 스케줄: 시작 소수 → 카운트다운 진행에 따라 점진 증가 → 마지막에 부족분 즉시 채움. 현황판 인원=사람+봇. 봇 이름·외형은 기존 `BotNames`·로스터 재사용.
- **번지(연출형)**: 서버가 점프 시작 시 고정 낙하-반동 곡선으로 점프자 위치를 구동(곡선 데이터화). 한 명씩(큐 또는 사용 중 거부), 점프 후 짧은 쿨다운, 사망·피해 없음. 클라는 카메라 흔들림·FOV 가속 연출. 반동 최고 높이를 점프자별·방 단위 최고로 기록해 전광판에 전달.
- **전광판(1차)**: 카운트다운·인원·번지 최고 높이만. **(2차)**: 번지/사격 TOP3·지역 안내·팁 순환(기록은 대기 안에서만, 서버 저장은 범위 밖).
- **구현(2차, 2026-11-20)**: 사격장 = 부스마다 사대+레인+TrainingDummy 몸 치수 표적 2개, 사대에 들어서면 서버가 VK-9·탄 60을 빈 슬롯에 빌려주고 나가거나 출발하면 회수, 방이 열린 동안 발사는 부스 안 대여 총만·표적 명중만 점수·사람/봇은 피해 계산 없이 멈춤(ADR-501). 전광판 = 카운트다운/번지 TOP3(점프 횟수)/사격 TOP3(명중 수)/지역 안내/팁을 `SecondsLeft` 기준으로 순환(모든 클라 동일), 순서·주기·팁은 rules.json `Island`, 기록은 `WaitingRecordsBroadcast`로만 전달되고 섬이 닫히면 비움(ADR-502). 로비 프로토콜 6.
- **네트워크**: 대기 상태·카운트다운·인원·기록은 서버→클라 복제(관측 가능한 범위만). 바 대역폭/틱 비용은 본 판 대비 작아야 함(섬 인원 ≤ 판 상한 80).
- **메인 메뉴 로비**와 코드·씬 분리 유지. 대기 섬은 매칭 후 전용 진입.
- **재접속**: 대기 중 끊김은 기존 재접속 창(`ReconnectSeconds`) 규칙을 따라 섬 위치에 복귀.

## Testing Decisions
- 좋은 테스트 = 외부 행동만 검증(남은 시간·시작 사유, 클램프된 위치, 피해량, 번지 위치 곡선, 슬롯 배정). 내부 구조 비검증.
- **가장 높은 seam = 서버 대기 흐름 전체**(매칭 확정→섬→카운트다운→투입)를 헤드리스 서버 시뮬로 구동하는 테스트 하나. 그 아래는 순수 규칙 EditMode(카운트다운·합류 스케줄·클램프·곡선·사격 허용). 새 seam은 이 둘뿐.
- 선례: `MatchQueue`/`ServerRules`/`Deployment` 규칙 테스트, `ServerFrameStats`·`--perf` 측정, 봇 통계 하네스(`BotFarmStats`), 네트 스모크(NetSmokeFixtures).
- 성능: 섬 장면 드로우콜·SetPass·삼각형·서버 ms를 PERF_BUDGET 합격선으로 판정(티켓마다 확인, 위반 시 머지 금지).
- 시각 확인은 스크린샷 캡처(준환 성향: 직접 엄격히 판정).

## Out of Scope

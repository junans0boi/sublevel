# 명중 분산 원인 분리 (#401, S2b) — 2026-11-17

독점 창(Unity·서버 다른 것 없음, 오디오 비활성), 브랜치 `claude/sync-lagcomp-7d48a6`. 측정 `LagCompShotScatterTests`(확산 0, 9 m, 호스트가 4.7 m/s로 좌우 걷기, Rifle), 분석 `tools/lagcomp_scatter.py`, 원자료 `lagcomp_shot_scatter.csv`(518발). 구성당 5회×12발(약 58발), 왕복 시뮬레이터 0/100/150 ms(양쪽 각 절반) × 사본 보간 1/2/3틱, 손실 0. 제품 코드 변경은 `LagCompensation.Probe`(테스트용 훅) 하나. 시뮬레이션 100 ms의 실제 핑 표시는 약 133 ms였으므로(S5) 아래 "100"은 실제 약 130 ms, "150"은 약 180 ms다.

## 샷별 기록
`dt` = 서버가 되감은 시각 − 그 순간 사본이 보여 준 시각(서버 위치 기록에서 사본 위치를 찾아 역산). `dt > 0`이면 되감기가 모자람(몸이 사본보다 앞). 몸 반폭 0.3 m ÷ 4.7 m/s ≈ **허용 ±64 ms**. `dt = 올라가는 시간(call→exec) − 되감기 모델 + 사본 지연`.

## 판정
1. **주원인은 분산이 아니라 체계 오차(평균 편향)다.** 구성 안 표준편차는 12~26 ms(0.06~0.12 m)로 허용(±64 ms) 안이고, 명중을 가르는 것은 평균 dt다.
2. **(핑 0~80 영역) 모델이 한 틱(33 ms)쯤 모자란다**: 현행 보간 2에서 dt +33 ms, 가끔 +64 초과 → 84%. 사본이 보간 틱 외에 항상 ~70 ms(S2)만큼 뒤처지는데 모델은 `ViewTick = 마지막 틱 − 2`만 뺀다. 보간 1로 사본을 33 ms 덜 늦추면 dt +10 ms로 100%.
3. **(핑 ≥ ~100 영역) 되감기 상한 0.25 s가 100% 걸린다**: 필요 되감기 평균 305 ms(p95 334)가 상한을 넘어, 모델이 250으로 고정(표준편차 0~6)되고 dt가 +55 ms(≈한계)로 93%, 150에서는 필요 347 > 250으로 dt +94 ms → **5%**. 상한 0.30도 150(실제 ~180 ms)에는 모자라며(필요 ~347), 보간 1 + 모델 보정으로 필요량을 ~314~(−33 ms)로 줄여야 닿는다.
4. **분산 출처(분산 몫, 상한 안인 0 ms)**: 모델 양자화 ≈ 51~57%, 사본 지연 지터 ≈ 42~49%, 올라가는 시간 ≈ 0%(표준편차: 모델 16 ms, 사본 지연 14~16 ms, 올라가는 시간 1 ms). 상한이 걸리는 영역에서는 모델이 상수라 분산이 전부 사본 지연 지터(표준편차 10~22 ms).
5. 속도 가정은 원인이 아님: 실측 4.70~4.73 m/s로 일정(표준편차 작음).

## 정정
S2 보고서의 "기준선(왕복 100, 보간 2)에서 사본 지연 181 ms가 모델·상한 안이라 상한 상향 근거 없음"은 **철회**한다. 상한이 비교한 값은 사본 지연이 아니라 **올라가는 시간(≈100 ms)까지 더한 필요 되감기(≈305 ms)**이다. S1·S2의 모델 열은 호출 시점 틱으로 계산해 올라가는 시간(약 3틱)을 빠뜨렸고 실제 서버 모델은 상한 250에 붙어 있다.

## S3 권장
- **상한 0.25→0.30(ADR, 공정성 비용 기록)**: 필요함. 현행 필요 되감기가 100 ms 구성에서 이미 평균 305 ms. 단 0.30으로도 실제 핑 ~180 ms는 못 덮는다(Q1의 150 ms 허용선은 실제 핑 기준이므로 시뮬레이션 100 ms ≈ 실제 130 ms까지가 목표라면 0.30으로 충분: 필요 p95 334 → 보간 1이면 ~300).
- **모델 보정**: 사본이 보간 틱 외에 ~2틱(70 ms)을 더 늦게 보이므로 `ViewTick`에 반영(`LagComp.InterpolationTicks` 2→3 상당) 또는 보간 1로 사본 지연 자체를 줄임. 보간 1은 100%/100%로 가장 좋지만 지터·손실에서 부드러움 미검증 → S3에서 이동 부드러움 회귀를 같이 본다.
- 핑 0~80 합격 기준 확인을 위해 시뮬레이션 50·80 ms 구성을 S4 매트릭스에 넣는다(여기서는 0/100/150만 측정).

## 1. 현재 생성기가 하는 일 (실제 수치)
출처: `WorldSpec.cs`(world.json), `WorldGenerator.cs`, `WorldPlan.cs`, `BuildingPlan.cs`, `rules.json`.
| 항목 | 현재 값 |
|---|---|
| 섬 | 1024 x 1024 m 지형, 둥근 사각형 해안(반경 420 m), 육지 약 0.65 km², 도로 합계 약 4.4 km |

| 배치 방식 | 도로 양옆에 줄 세움(`PlaceLots`: 도로 끝에서 `LotSetback` 5.5 m, 건물 사이 `LotGap` 7.5 m). 블록·골목·광장·울타리 개념 없음, 건물 간 거리가 7.5 m 이상이라 붙은 상가거리 불가 |
| 도로 | `Trunk`(6 m)/`Spur`(4.5 m)/`Path`(2.5 m), 경사 12도 이하, 평탄화. 격자 아님 |
| 건물 내부 | 코드 조립 상자(벽·문·창·계단, 방마다 가구 `RoomRole`), 지붕 평평, 회전 부품 없음 |
| 소품 | 바위·나무 산포(`ScatterPoint`)뿐. 차량·울타리·감시탑·컨테이너는 `WorldPlan`에 데이터가 없음(차량은 별도 시스템) |
| 인원 | `MaxPlayers` 16, 봇 15(최대 23). 자기장 원 없음: **지역 순차 봉쇄**(SPEC 3, 지역 단위 + 소구역 SubZone) |
| 투입 | 엘리베이터(무작위 지역, 보호 6초). 비행기 낙하 없음 |

결론: "5명이 사는 마을" 느낌의 원인은 (1) 단지당 3~7채, (2) 건물 간 7.5 m 이상 띄워 줄 세우는 배치, (3) 블록·골목·담이 없어 엄폐가 건물 외벽뿐, (4) 용도 종류가 5개라 학교·상가·아파트가 없음.

## 3. 추천: B 기반 + A의 블록 도심 이식(=B+)
- 이유 1: 사용자 불만(밀도·시가전)은 **블록 생성기**를 만들면 풀린다. 이는 모든 안이 공통으로 필요하고, 도로 줄 세우기를 격자·블록으로 바꾸는 일이다.
- 이유 2: B의 "마을 6곳 균등" 구조가 SPEC 3(최종 구역 매 판 랜덤, 폐쇄 후에도 연결)과 현재 지역/엘리베이터/봉쇄 구조를 거의 그대로 쓴다. A는 도심이 최종 구역으로 굳을 위험, C·D는 지형 트랙 일정에 묶임.
- 이유 3: 순환로는 차량과 봇 순찰·교전 흐름이 가장 단순하다. 지형(산·강) 작업이 늦어져도 평지 위에서 레이아웃을 먼저 검증할 수 있다.
- 방식: B의 6곳 중 북읍을 A식 도심(40~70채)으로 키우고 나머지는 22~34채로 둔다. 모티프 혼합: 북읍·남읍 = 1980년대 한국 읍내(상가거리·아파트·학교·시장), 서평·남동 어촌 = 열대 논·수상가옥·부두. 사용자가 A를 고르면 도심 하나를 더 키우면 되므로 되돌리기 쉬움.
- 위험: (a) 마을이 서로 비슷해 보임 -> 마을마다 고유 구조물 1개(학교, 공장, 부두, 광산)를 필수로. (b) 순환로 매복 -> 도로 양옆에 엄폐물을 일부러 둠.

## 4. 안별 생성기 변경 (기존 클래스 기준)
공통(모든 안):
- `BuildingKind`(`BuildingPlan.cs`): `Shophouse, Apartment, School, Barracks, Gym, GuardTower, Greenhouse, Container, Stilt` 추가. `Buildings.cs`에 종류별 생성, `BuildingRules.MaxPieces`에 부품 상한.
- `WorldGenerator.PlaceLots`: 도로 줄 세우기 -> **블록 기반 배치**(격자 도로 + 블록 안 이중 줄 + 골목 3~4 m). `LotGap` 7.5 m를 종류별로(상가 붙임 0.4 m, 주택 2~4 m)로 완화. 단 도로 평탄화 패드가 겹치므로 `WorldTerrain.AddRectPad` 블렌딩 규칙 재검토.
- `WorldPlan`: `Fences`(울타리·담), `Props`(차량·상자·엄폐벽·좌판), `Fields`(논·밭·태양광), `Rivers`(C·D만) 목록 추가. `WorldRules`에 새 규칙(블록 안 건물 접근성, 골목 통로 최소 폭 2.2 m, 건물당 출입문 연결).
- `WorldSpec/RegionSpec`: `RegionKind`에 `Port, Farm, School(Compound)` 추가 또는 `Town` 하위 템플릿. `CompoundLots` 3~7 -> 22~46(북읍 60). 마을 템플릿 필드(`BlockGrid`, `AlleyWidth`, `StoreyMix`).
- `Furniture.cs`/`RoomRole`: 학교(교실, 교무실), 상가(매장), 아파트(거실), 막사 방 역할.
- `WorldBuilder`/`WorldMaterials`/`MapBaker`(Editor): 새 부위 재질 매핑, 지도 베이크에 울타리·밭 표시.
- `Vegetation.cs`: 논 격자, 가로수 간격, 밭두렁.

A: 위 공통 + 방사 도로를 `Trunk`로 도심에 수렴시키는 `AddTrunk` 조정, 도심 하나 큰 `CompoundLots`(~76), SubZone 분할을 도심 안에서 블록 단위로(소구역 폭격 이전에 최종 결전이 도심 블록 단위가 됨).
B: 공통 + 순환로 `Trunk` 폐곡선 생성(지금 `Trunk`는 고개를 통과하는 지역 연결선이므로 새 종류 `Ring` 필요) + 마을을 링 위 6곳에 배치(`ConvergencePoints`와 엘리베이터는 현재 구조 유지). 가장 작은 변경.
C: 공통 + `WorldTerrain`에 강(폭 40~60 m 하상, 수심, 흐름 없음), `WorldRoad`에 다리(`Bridge` 구간, 내비메시 링크), 양안 지역 분할(보로노이 대신 강 경계), 수영 가능한 폭. `Pass` 개념을 다리로 일반화.
D: 공통 + 능선(`RidgeHeight` 34 -> 60~90 m), `MaxRoadSlopeDeg`/`MaxLotSlopeDeg`(20도) 완화 또는 계단식 평탄화, 선형 마을 배치(도로 곡선 따라 블록), 병영 고지의 별도 `Flatten`. 내비메시 경사 설정 변경.

## 7. 다른 트랙과의 경계
- 산·강·지형 구현 방식은 지형 트랙. 이 문서는 C·D가 요구하는 강·능선의 "배치 요구"만 적었다.
- 맵 에셋 조달 트랙: 5장은 필요 분류 목록까지만, 실제 에셋 선정·다운로드는 그 트랙.
- 캐릭터·애니메이션·누락 점검 트랙의 항목은 포함하지 않았다.

## 8. 알려진 한계
- 개요도·확대도는 의도 수준 개략도이고 생성기가 만든 실제 좌표가 아니다. 건물 수는 자체 스크립트 집계(확대도)와 손으로 정한 개요 수치다.
- 실제 PUBG 맵 사진은 사용하지 않았고(첨부 이미지 미열람), 건물 수 범위는 사용자 설명(25~60채)을 따랐다.
- 성능(M4 Pro)은 측정하지 않았다. 건물 약 200채는 현재 약 78채의 2.5배라 PERF_BUDGET 재측정이 필요하다.

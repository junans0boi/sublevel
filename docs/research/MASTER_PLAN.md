## 0. 목표와 원칙 [보강]
- **느낌**: 배틀그라운드급 몰입(완전 실사 아님). Low Poly 느낌을 벗는다 = 재질·조명·비율·소리·동작 다섯 가지를 같이 올려야 한다. 한 가지만 올리면 오히려 어색하다.
- **오리지널**: 한국 1980년대 + 열대 혼합의 가상 세계. 실존 상표·총기·차종명·지명 복제 금지(CLAUDE.md 규칙 1).
- **50명/판**(사람 + AI 봇). 사람 수가 달라도 같은 규칙.
- **결정 방식**: 시각·청각처럼 취향이 걸린 것은 에이전트가 후보를 만들고 준환이 직접 보고/듣고 고른다.
- **검증 방식**: "시트 이미지만 보고 판단" 금지(내가 사망 클립을 오판한 전례). 수치(좌표·높이·테스트) + 게임 안 캡처 둘 다 요구.

## 1. 재질 (Material)
**의도(준환)**: Low Poly 느낌이 강함 → 살짝 배그 같은 질감으로.

**[보강] 선정 기준과 범위**
- 표면 분류 12개(C2 노트 기준): 아스팔트, 보도·콘크리트, 흙길·자갈, 외벽(콘크리트·벽돌·목재), 지붕(기와·골함석), 실내 바닥, 금속, 농지(논·밭), 식생, 물, 태양광, 학교·막사 마감. 신규로 구할 것: 아스팔트·보도·기와·골함석·논·벽돌.
- 후보는 Poly Haven(CC0)에서 Chrome으로 직접 보고 고른다. 각 후보: ID, 링크, 해상도(1k/2k/4k), 타일링, 용량, 분위기(80년대 한국/열대) 적합 이유.
- **파이프라인**: 현재 `WorldMaterials`는 ambientCG 맵(roughness/ao/metallic 분리)을 마스크로 합친다. Poly Haven은 `arm`(AO·Rough·Metal 한 장) 형식이라 이미 `PackRockMask`가 있다. 표면 전부를 `arm` 경로로 통일할지 `?`.
- **조명 일관성**: 하늘이 맑은 Kloofendal HDRI로 바뀌었는데 `WorldBuilder`는 흐린 하늘 가정(안개 색, 그림자 50m, 앰비언트, 반사)이다. 재질만 바꾸면 어울리지 않는다 → 같은 작업 묶음에 넣는다. 실내 리플렉션 프로브 부재로 PBR 실내가 밝게 새는 문제도 포함.
- **디테일 3종**: 지형 블렌딩/트라이플래너(타일 반복 감추기), 데칼(얼룩·균열·젖음), 정점 색 변주.
- **용량 예산**: 이번 주 받은 텍스처 173MB는 미사용. 쓰는 것만 남기고 해상도 상한(예: 2k 기본, 지형 4k 소수)을 정한다 `?`.
- **완료 기준**: 같은 구도의 전/후 캡처 비교 + 성능 예산 통과(렌더 콜·VRAM).
- **담당**: 재질 에이전트(조사) → 구현은 단독 에이전트(Unity).

## 2. 사운드
**문제(준환)**: 총소리·걸음·창문 깨짐이 "스타워즈" 같다. 2층 상대의 발소리 방향·층이 들려야 한다. 후보를 조사해 오면 준환이 전부 듣고 선택한다.

**[보강] 현황 먼저**: 지금 오디오 구조는 `docs/AUDIO.md`, `CombatantAudio.cs`, `BulletSurfaces.cs` 참조. 발소리/탄흔 재질이 **오브젝트 이름에서 건물 종류를 파싱**해 정한다(조용히 Concrete로 떨어짐) → 데이터 기반 표면 태그로 바꿔야 한다. 표면은 현재 6종뿐.

**공간음향 설계안**
1. **방향·거리**: 3D 감쇠 곡선을 소리 종류별로(총성 수백 m, 발소리 30~40m). HRTF 사용 가능 여부는 Unity 6 오디오 확인 필요.
2. **수직(층)**: 같은 건물 다른 층이면 바닥 차폐(저역 통과 + 감쇠) + 계단·천장 방향 단서. 상대 높이 차를 오디오에 반영.
3. **차폐/폐색**: 소스–리스너 사이 벽 수만큼 저역 통과 + 볼륨 감소(레이캐스트 샘플링, 비용 제한).
4. **실내/실외 잔향**: 지역·방 단위 리버브 존(실내, 계곡, 도심 골목, 숲, 물가). 총성은 근거리(직접음) + 중거리 + 원거리 꼬리 3겹, 실내/실외에 따라 다른 꼬리.
5. **표면별 발소리**: 표면 태그 × 속도(걷기/달리기/웅크림) × 신발/자세. 계단·금속 계단·유리 파편 포함. 젖은 땅·물 첨벙.
6. **행동음 전부**: 총기별 발사/장전/격발 공이, 탄피, 근접, 문, 창문 깨짐(유리 두께별), 아이템 줍기, 치료, 차량(엔진·타이어·충돌), 피격(부위별), 수영, 낙하, 폭발·섬광탄 귀울림.
7. **환경음**: 지역별 앰비언스(도심 바람·전선 윙윙, 숲, 강, 바다), 날씨, 오염 지대(가이거 계수관 소리 등).
8. **믹서·우선순위**: 50명이 동시에 쏠 때 폭주 방지(보이스 제한, 거리 기반 우선순위, 서버가 소리 이벤트를 관심 영역 안에만 전송).
9. **네트워크 연동**: 소리는 이벤트로 동기화(발사, 걸음 간격은 클라이언트 계산).

**소스 조사 방식 (준환이 들어보고 선택)**
- 에이전트가 후보를 라이선스 확인된 곳에서 모은다: Freesound(파일별 CC0만, CC-BY는 크레딧 가능 여부 `?`), Sonniss GDC 번들(상업 가능, 원본 단독 재배포 금지 `확인 필요`), Kenney Audio(CC0, 스타일 단순), OpenGameArt(CC0만), 직접 합성(레이어 합성). 비상업(NC)·BBC류 금지.
- **청취 시트**: 후보를 소리 종류별(총성 ×N, 발소리 표면별, 유리 깨짐 …)로 HTML 오디오 플레이어에 모아 라벨·라이선스·출처 링크와 함께 보여준다. 준환이 A/B로 고른다. (다운로드는 임시 폴더에만, 선택된 것만 저장소에 넣고 ASSET_LEDGER 기록.)
- 실제 총기 녹음 소스가 없으면 "다층 합성(폭발음 + 금속 + 꼬리)"이 현실적 대안.
- **완료 기준**: 같은 건물 2층 사격/걷기 시연에서 방향·층 구분 테스트(자동 테스트 + 준환 청취).
- **담당**: 사운드 소스 조사 에이전트 + 공간음향 설계 에이전트(별개 파일 소유).

## 3. 네트워크·성능 (50명/판)
**준환**: 방당 50명(봇 + 접속자). 동기화 중요.

**[보강] 결정해야 할 것과 제안**
1. **권위 구조**: 서버 권위(Fish-Net) 유지. 전용 서버(`docs/DEDICATED_SERVER.md`) 기준 설계. 봇은 **서버 안에서만** 시뮬한다 → 봇이 많을수록 서버 CPU 부담.
2. **관심 영역(Interest Management)**: 거리 + 지역 기준 관찰자 조건. 문·유리·루팅 오브젝트·차량의 상태/이벤트는 관심 영역 안에만 전송. 현재 문·유리가 전 클라이언트에 Broadcast되는 점이 병목.
3. **봇 AI LOD**: 먼 봇은 낮은 틱, 단순 이동만. 사람이 없는 지역 봇은 거의 정지/저비용.
4. **지연 보상**: `LagComp`의 복잡한 지오메트리(건물 내부) 비용 측정.
5. **대역폭/틱 예산**: 플레이어당 업링크·다운링크 목표치와 틱레이트를 정한다 `?` (수치는 조사 후 제안, 지금은 근거 없음).
6. **스트리밍**: 411채 건물을 한 번에 두면 드로우콜·메모리 폭발 → 지역 단위 로드·정적 배칭·오클루전 베이크·LOD. 성능 예산(150만 삼각형, 555콜)을 어떻게 지킬지 측정 방법 추가(메모리 3GB, 로딩 5초는 판정 방법 없음).
7. **매치/방**: 방 생성·빈 자리 봇 채우기·재접속·관전. 접속 지연 상한.
8. **테스트**: 헤드리스 클라이언트 N개 부하 테스트(예: 49 + 1)로 서버 CPU·대역폭 측정. CI에 넣을 수 있는 최소 버전.
9. **치트**: 서버 판정, 이동 속도 검증, 정보 은닉(시야 밖 적 정보를 보내지 않기).
- **담당**: 네트워크 에이전트(설계) + 성능 에이전트(측정 방법) → 구현 순차.

## 4. 애니메이션
**준환**: 캐릭터도 Humanoid, 애니메이션도 Humanoid로.

**[보강] 단계**
1. **캐릭터 선정**: Mixamo 사실풍 + Quaternius UBC 조합(01번 보고서 추천). 준환이 시험용 Mixamo FBX 1종을 받아 폴리 수·텍스처 임베드·Avatar 유효 확인.
2. **임포트 규칙**: Humanoid 아바타 자동 구성, Mixamo 애니 FBX도 Humanoid로 재임포트(지금은 Generic).
3. **애니메이터 구조**: Base(이동 2D 블렌드 + 자세), Upper(조준·사격), Action(장전·꺼내기·치료·투척), Additive(반동·시선). 시선 피치 분배는 Humanoid 본에 적용.
4. **IK**: 왼손 파지(총 소켓 `LeftHandGrip`) + 발 IK. 스프린트에서 왼손이 꺼져 팔이 흐물거리는 문제가 이번에 해결되는지 확인.
5. **클립 세트**: 저장소 보유(서기·조준·달리기·걷기·후진·옆걸음·사격·장전 3자세·웅크림 이동·사망) + 부족분(스프린트, 점프·착지, 회전, 피격, 엎드려 기기·눕기, 근접, 투척, 치료, 권총, 수영, 파쿠르, 차량 앉기, 에모트). 소스는 Mixamo/UAL.
6. **엎드림**: 지금 85도 눕힘 + 40도 머리 들기(의도값). 실사 비율에서는 몸통이 거의 수평이어야 하므로 값/방식 재설계.
7. **무기 비율**: 소총 길이를 실물 기준으로(Sentinel 1.05m → AK급 0.87m 등), 권총 0.24 → 0.19m.
8. **1인칭 팔/뷰모델**: 현재 자체 프리미티브. 새 캐릭터 팔을 쓸지 `?`.
9. **사망/래그돌**: 지금 래그돌 없음. 사망 클립 + 선택적 래그돌 `?`.
10. **테스트**: 코드 포즈 수치를 고정한 테스트(`StanceTests`, `ReloadMotionTests` 등)는 "결과 기반"으로 교체. 공개 속성(`PronePose` 등)은 유지해 PlayMode 수정량 최소화.
- **담당**: 캐릭터 시험 임포트 에이전트 → 애니메이션 구현 에이전트(Unity 순차).

## 5. 맵
**준환 요구**: 한강식으로 강이 지역을 나누고 다리로 건넘, 산등/산맥 전투, 시가전. 바다·도시·강·산맥 외에는 전부 국도로 연결(강은 다리). 산 꼬깔 개선.

**[보강] C2안 기준 확정 수치(제안, 준환 승인 필요)**
- 섬 2.4×2.0km, 육지 약 3.2km². 50명 → 15.5명/km². 마을 17곳(수도급 청람읍 90채, 대형 4, 중형 6, 소촌 6), 건물 411채(진입 305). 지역 6개. 엘리베이터 승강장 20곳. 도로: 국도 2.8, 포장 8.2, 비포장 1.3km. 차량 고개 5, 보행 안부 3, 다리 5.
- **지형**: 최고 203m, 걷기 가능(≤35도) 86%+ 목표. 3번 문서: 능선 골격 → 도메인 워프 → 테라스 → 협곡 → 절벽 마스크 → 안식각 제한. 컨트롤러 `slopeLimit` 45 vs 규칙 40 불일치 정리(ADR).
- **도로**: 연결 그래프(순환 8). 도로 경사 ≤12도(시안은 일부 초과 → 고갯길 재설계). 도로 NavMesh/차량 경로. 도로 위 분기·검문소·차량 엄폐.
- **도시 구조**: `PlaceLots`를 블록·골목으로, 건물 종류 5 → 상가·빌라·학교·막사·감시탑·고상가옥·비닐하우스 등. 층수 1~2 → 2~5. 계단·옥상·창문 사격. 도심 최대 90채.
- **산악 전투**: 경사대별 엄폐 밀도, 전망점 5, 능선 교전지 3, 채석장 2, 사각지대 협곡.
- **물**: 강(수영·얕은 여울·다리), 바다 해안, 수영 속도.
- **랜드마크/POI**: 지역별 특색 1~2개(리조트, 병영, 학교, 항구, 채석장 등). 종교 상징은 RISKS에 올리고 보류.
- **파밍**: 건물 종류·지역별 가치 표(지금은 전역 1개 테이블, `MaxLootSpawns` 250 상한). 50명 기준 총량.
- **차량**: 스폰 위치(도로·마을), 종류, 연료.
- **식생**: 열대 야자·정글, 한국식 침엽/활엽, 논·밭. (CC0 야자는 자체 제작/Yughues 후보, 건물 완성품은 코드 생성.)
- **날씨/시간대**: 맑음 기본, 비·안개·밤(이미 일부 구현). 오염 시각 효과와 연동.
- **지도 UI**: 2048px/128m 그리드 → 새 섬 크기에 맞춰.
- **저장소 용량**: 월드 메시 42MB + 씬 32MB(텍스트 YAML) → 411채에서 100~200MB. LFS/런타임 생성 `?` (이슈 #240).
- **담당**: 지형·도로·도시 생성기 에이전트 3개(파일 소유 분리).

## 6. 최종 지역 시스템 (오염/방사능)
**준환 아이디어**: 자기장 대신, 핵/방사능에서 착안해 특정 도시를 오염시켜 데미지 + 출입 차단 → 결국 최종 지역에 모이게.

**[보강] 현재**: SPEC §3의 "지역 순차 봉쇄"(지역 4개, 엘리베이터 3~4대/지역)가 이미 있다. 이름만 "봉쇄"이고 규칙이 애매하다고 판단 → 아래 결정으로 확정.

**설계 대안 (준환 선택 `?`)**
- **A. 지역 오염**: 6개 지역을 순서대로 오염(타이머 + 사전 경고). 진입하면 즉시 지속 데미지(DPS 상승).
- **B. 확산 오염**: 오염원에서 전선(front)이 일정 속도로 퍼짐. 자기장과 비슷하지만 "원"이 아니라 지형·도로를 타고 번져 오리지널 느낌.
- **C. 하이브리드(제안)**: 지역 단위로 "오염 확정 → 전선이 도심 쪽으로 수렴 → 마지막 지역 하나만 남음". 지역은 강·산 지형으로 나뉘므로 다리·고개가 병목이 되어 이동 전략이 생김.
- **결정 항목**:
  1. 출입 차단 방식: 물리적 차단(게이트/벽)인가, DPS만 올리는가? (완전 차단은 이미 안의 사람을 어떻게 하는지 필요: 데미지로 밀어냄)
  2. 경고: 사이렌/방송/지도 표시, 오염 몇 초 전 예고, 예고 시간 `?`.
  3. 시간표: 판 길이 목표(예: 20~25분), 단계별 대기·진행 시간 `?`.
  4. 아이템 연동: 방독면, 해독제, 방호복 → 일시 진입 허용(전략 요소) `?`.
  5. 차량: 오염 지대 통과 가능 여부, 다리 폐쇄.
  6. 최종 지역: 후보(청람읍 도심 등)와 최종 면적. 지역 순서는 무작위(시드) + 항상 육로로 이어지게(C2 "폐쇄 순서 뽑기" 방식).
  7. 시각/청각: 붉은 안개, 가이거 계수관, 화면 효과.
  8. 봇 AI: 오염 회피·이동 목표, 최종 지역으로 수렴.
  9. 네트워크: 시드와 서버 시간으로 결정론적 계산, 상태는 지역/전선만 복제(작은 데이터).
  10. 규칙 변경이므로 **ADR 필수**(규칙 5), SPEC §3 개정.
- **담당**: 오염 시스템 설계 에이전트(규칙·수치 시뮬레이션 HTML로 보여 주기) → 준환 선택 → 구현.

### 8.4 운영 규칙
- 에이전트는 자기 소유 파일만 쓴다. 공유 데이터 계약(표면 태그, 지역 ID, 도로 그래프 포맷)은 먼저 문서로 합의한 뒤 구현.
- 동시 실행 상한 4~5(비용·충돌). 보고서는 한국어 요약 10줄 + 체크리스트 형식 고정.
- 에이전트 보고는 "추정/확인"을 구분해 적게 한다(위 문서들처럼). 준환에게 올리는 보고에서도 미확인은 미확인으로.
- 외부 다운로드·약관 동의·결제는 에이전트가 하지 않는다(규칙 3). 사람이 할 일은 목록으로 모아 준환에게.

# S6 → S1: 오염 코어가 맵에서 받아야 하는 데이터 (2026-11-16)

오염 코어(`Core/PollutionFront.cs`)는 Unity를 모르는 순수 C#이다. 맵 생성기가 아래를 **매치 시작 전에** 만들어 주면 된다.

## 1. 오염 그리드 `PollutionGrid`
| 필드 | 형식 | 의미 |
|---|---|---|
| `Width`, `Height`, `CellMeters` | int, int, float | 지형 박스를 덮는 격자. 기본 12 m(C2 시안 200×167). 더 거칠어도 되지만 시뮬레이터 수치(전선 속도 조정)는 12 m 기준 |
| `Region[i]` | byte | 지역 번호 0..N-1. 바다·섬 밖은 `255` |
| `SlopeDeg[i]` | float | 그 셀의 지형 경사(도). 강 셀은 0 |
| `Road[i]` | byte | 0 없음, 1 비포장, 2 포장·국도·다리 (셀 중심이 도로 폭 안이면 큰 값) |
| `River[i]` | bool | 강·하천 셀(바다 아님). 지역 번호는 강 셀도 가진다 |
인덱스는 `y * Width + x`, 월드 좌표 → 셀은 `PollutionGrid.CellAt(xMeters, zMeters)`(원점 = 지형 박스 모서리). 해안 셀은 코어가 직접 계산한다(이웃 8칸 중 바다이거나 그리드 밖).

## 2. 지역 인접 그래프
`int[][] adjacency` — `adjacency[r]` = r과 **육로로 맞닿은** 지역 번호. 지금은 `map.json` 값 `R0:{1,3,4} R1:{0,4,2} R2:{1} R3:{0,4,5} R4:{0,3,1,5} R5:{3,4}`. 그리드의 이웃 셀 지역이 다르면 인접으로 보는 것과 같다(시뮬레이터 방식, 같은 결과 확인됨). 코어는 이 그래프만 보고 "남은 지역은 항상 이어진다"를 보장한다.
- **강 경계도 육로로 본다**(다리 5·여울 1로 국도가 이어지므로). 다리가 끊기는 설계가 되면 알려 달라.

## 3. 승강장 목록
승강장마다 `(region, 월드 위치)`: 열쇠 승강기 상태 머신(`KeyElevatorStation`)과 칩 보관함의 소유 지역을 정한다. 기존 `ElevatorSlot`/승강장 데이터에서 지역 번호만 있으면 된다.

## 4. 루팅 가중치
`regionWeight[r]`: 지역별 루팅 점 수 또는 면적(열쇠 배치의 기본 가중치, 없으면 균등). S1의 루팅 점 계획과 같은 값을 쓴다.

## 5. 변경될 때 알려야 하는 것
- 지역 수 6 이외로 바뀜: `PollutionRules.ConfirmMinutes`·`Dps`(6단계)와 `adjacency` 크기를 같이 바꾼다. 지역 번호는 byte이고 255는 바다 예약이라 최대 255개까지 코어가 처리한다.
- 격자 해상도 변경: 시뮬레이터 대조 테스트는 `PollutionSimFixture.txt`(C2 시안 격자)를 계속 쓰므로 영향 없음. 새 맵은 판 길이(20~25분)를 다시 본다.
- 도로 경사 12도 재설계(WP 3): 도로 셀이 `Road`에 반영되어야 한다(전선 속도에 영향).

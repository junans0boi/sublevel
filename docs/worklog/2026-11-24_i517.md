# 2026-11-24 — #517 레이스 밸런스: 차 5대 × 코스 4개 랩 측정, RaceVehicleModels 조정

- 목표(스펙 #505, ADR-562 (1)): 코스마다 차 5대의 고정 실력 랩을 헤드리스로 재서 ① 모든 코스 1등인 차가 없고 ② 코스별 최고↔최저 차이 ~6% 이내가 되게 레이스 행을 조정.

## 측정 방법 (`Tests/PlayMode/RaceBalancePlayTests`, Explicit, Category Balance)
- 실행: `tools/unity.sh test playmode Game.Tests.RaceBalancePlayTests` (4개 코스, 약 4분). 로그 `[RaceBalance] <코스>: ...` 한 줄씩, 코스별 편차 ≤ 6% 를 단언.
- 각 코스 레이스 씬을 로컬 호스트로 열고, RaceDirector는 끈다(씬·코스·레이스 규칙만 씀, 봇/랩 판정 안 씀). 차 5대를 직접 스폰(Autopilot), **혼자 달리는 타임트라이얼**: 순환(스네이크·고개 순환)은 랩의 18% 간격으로 동시에 놓고 **플라잉 랩**(결승선 두 번째 통과까지), 스프린트(업힐·다운힐)는 12초 간격으로 출발선에서 한 대씩 **스탠딩 런**. 서로 부딪히지 않는다.
- 드라이버: RaceBotDriver의 라인·코너 계획(같은 Aim, 같은 80 m 앞보기, 실력 0.9 고정)을 쓰되 **그 차의 한계**로: 부스트 최고속(부스트 상시), 타이어 그립(봇과 같은 여유 비율 1.05/1.15), 브레이크(6/9 비율). 이벤트 봇(RaceBotDriver)은 90 km/h·그립 1.05가 상수라 차 성격이 랩에 안 드러나서(고블린도 90에서 멈춤) 이 측정에는 못 쓴다 → 후속 거리.
- Time.timeScale 4 (물리 스텝 고정, 입력은 매 스텝) — 같은 차의 두 측정이 0.02초 안에서 일치(LT80 스네이크 129.76 / 129.78).
- 막혔을 때 되돌리기(봇과 같은 규칙)는 전 측정 0회.

## 테스트
- `RaceBalancePlayTests` 4/4 (튜닝 전은 업힐·다운힐·순환 편차 초과로 3개 실패).
- EditMode `VehicleHandlingRulesTests` + `RaceEventTests` + `RaceLobbyTests` 32/32.
- PlayMode `RaceEventPlayTests.Bots_FillTheGrid_AndEachDrivesALap`(이벤트 봇이 새 그립으로도 코스를 도는지) 1/1, 되돌리기 0회. 봇 7대의 최고 랩이 141.6~142.3 s로 차와 무관하게 거의 같음 — 아래 "봇은 차 성능을 모른다"의 증거.

## 남은 것 / 후속
- 이벤트 봇(RaceBotDriver)은 차 성능을 모른다(TopSpeed 25 m/s·Grip 1.05 상수, 부스트 안 씀) → 봇 레이스에서는 차 차이가 거의 안 나고, 그립 1.04인 고블린 봇은 봇이 가정하는 1.05보다 낮다(실력 ≤0.95라 실제 여유는 있음). 봇이 자기 차 행을 쓰게 하는 건 별도 티켓.
- 밴의 몸싸움 장점, 픽업의 비포장 장점은 이 측정으로 못 잰다(코스에 비포장 구간 없음).
- 랩 수치 조정은 ADR-562 (1)의 범위 안이라 새 ADR 없이 이 워크로그에 기록(마스터 판단).

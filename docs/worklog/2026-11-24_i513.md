# 2026-11-24 — #513 전용 서버가 로비 큐에서 레이스를 시작 (프로토콜 9)

- 스펙 #505, ADR-562 (4). #508의 `RaceStart`(`RaceEvent.Starting`)를 전용 서버까지 연결.
- 프로토콜 8 → 9: `LobbyQueueRequest` += `Event`(코스 1-based, 0 = 배틀로얄), `Laps`, `Bots`, `Car`(`VehicleHandling.Race` 인덱스), `Paint`. `LobbyStart` += `Laps`(0 = 코스 기본).
- 클라: `LobbyNet.RequestRace(partySize, evt, laps, bots, carModelId, paint)` — 범위 밖이면 보내지 않고 false. 파티 크기는 방 8자리까지(배틀로얄은 4).
- 서버(`LobbyNet.QueueRace`): `RaceEvent.ValidQueueRequest`로 범위 검증(코스, 랩 1/2/3/5, 봇 0..7, 레이스 차 5종, 색 0..5). 큐에는 **한 파티만**: 첫 요청이 코스·랩·봇을 정하고, 배틀로얄 요청·다른 파티(또는 파티 없는 두 번째 사람)의 레이스 요청은 받지 않음(반대로 배틀로얄 큐가 있으면 레이스 요청도 거절). 차·색은 연결별로 저장. 파티 인원(PartySize)이 다 모이면 즉시 시작(채우기 대기 없음), 안 모이면 큐 창(`QueueWindowSeconds`)이 끝날 때 온 사람만.
- 시작: `LobbyStart{Event, Laps, Bots = min(봇, 8 - 사람), Players, Mode = Solo}`를 파티원에게만 보내고, 서버는 `RacePlan`(`RaceStart{코스, 랩, 봇, People, 세션 토큰별 차·색}`)을 만든다. 배틀로얄 시작과 꼬리(`BeginQueuedMatch`)를 공유.
- `DedicatedServer`: `Event`가 있으면 `RaceEvent.Starting = RacePlan`, `World` 대신 `RaceEvent.SceneForLobby(Event)`를 열고(문 레이아웃 준비 생략), 레이스가 `Over`(결과 10 s 뒤)가 되면 바로 판을 끝내 로비로 돌아감(배틀로얄의 결정 후 20 s 대기 없음).
- `RaceDirector`(한 줄): 카운트다운이 서버가 기다리는 사람 수(`RaceStart.People`)까지 기다림(최대 `WaitForLoadSeconds`). 전용 서버에서는 첫 사람이 붙자마자 카운트다운이 시작돼 둘째가 봇 뒤 자리에 끼던 문제. 사람별 차·색은 #508의 세션 토큰 경로인데, 매치 서버가 세션 hello보다 플레이어를 먼저 스폰할 수 있어(`SessionKeeper.Intercept`는 보류가 없으면 바로 스폰) 첫 실행에서 a가 슬롯 차를 받았다 → 사람별 항목이 있는 레이스는 `Waiting` 동안 토큰이 올 때까지 좌석을 미룸(`TokenKnown`).
- `LobbyNet.SessionToken`: 로비 hello의 세션 토큰(기본 `NetSession.Token`). 한 프로세스에서 여러 로비 클라를 쓰는 테스트용.
- 덤: main의 `RaceBalancePlayTests`가 #508에서 없어진 `RaceEvent.Chosen`을 써서 컴파일이 깨져 있어 `Starting = new RaceStart { CourseId }`로 바꿈.
- 테스트: `RaceStartTests.QueueRequest_InRange_Only`(EditMode), `RaceQueueMultiTests`(PlayMode: 전용 로비에 두 파티원 + 다른 사람 → 다른 파티 레이스·배틀로얄 요청은 안 섞임, 파티가 다 오면 `LobbyStart` Event 1/Laps 1/Bots 2 → 서버 전용 레이스 씬에서 각자 고른 차·색, 사람 2 + 봇 2 = 4대, 1랩(코스 기본 2랩)으로 완주, 결과 뒤 `Over`).
- 범위 밖: 클라 `MainMenu`가 `LobbyStart.Laps`를 `RaceStart`에 넘기는 한 줄(#511 화면 세션 파일, 서버가 랩을 결정하고 `RaceStandings.Laps`로 보내 HUD는 이미 맞음). 누가 언제 `RequestRace`를 부르는지(백엔드 race 티켓 → 매칭 → 로비)는 #511/#514 몫. `DedicatedServer` 프로세스 자체의 끝내기는 서버 빌드가 없어 `DedicatedServerPlayTests`가 건너뜀 — `Over` 도달까지만 테스트.
- 결과: EditMode 98/98(`RaceStartTests;MatchQueueTests;QueuePartiesTests;LobbyTests;PartyLobbyTests;ServerArgsTests;RaceLobbyTests;RaceEventTests`). PlayMode `RaceQueueMultiTests` 통과(172 s), `LobbyPlayTests` 9/9, `RaceEventMultiTests`, `RaceStartPlayTests` 통과. `DedicatedServerPlayTests`는 서버 빌드(`Build/server`)가 없어 건너뜀.
- 관찰(범위 밖, 후속 후보): 서버 전용 레이스(한 프로세스 하니스)에서 그리드 차 몇 대가 카운트다운 중 "false start"(+1랩)로 찍히고, 봇 두 대가 출발선 뒤(s ≈ 2250–2290)에서 계속 "put back (stopped)"만 반복하며 출발하지 못함. 호스트 토폴로지 테스트에선 안 보이던 것 — 하니스의 복제 차 충돌일 수도, 실제 전용 서버 문제일 수도 있어 서버 빌드로 확인 필요. 테스트는 부정 출발 +1랩을 허용(LapsToGo ≤ 2 = 파티의 1랩)하도록 씀.

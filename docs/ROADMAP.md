# ROADMAP — 마일스톤과 게이트

원칙: 각 마일스톤은 **게이트**를 통과해야 다음으로. 각 마일스톤 안의 타이틀마다 WORKFLOW 루프를 돈다. 무거운 작업은 순차.

| M | 이름 | 목표 | 게이트(통과 조건) |
|---|---|---|---|
| M0 | 기술 검증 | Unity CLI 헤드리스 파이프라인 증명, 성능 기준선, 에셋 파이프라인 | ① 프로젝트 생성/설정/씬 생성 헤드리스 ② EditMode+PlayMode 테스트 헤드리스 ③ mac/win 빌드 성공 ④ 스크린샷/프레임타임 파일 추출 ⑤ Fish-Net 서버 권위 "호스트+클라" 스모크 ⑥ M1 13"에서 테스트 씬 프레임타임 측정 → PERF_BUDGET 수치 확정. **실패 시 Godot 4 폴백 ADR** |
| M1 | 코어 루프 | 이동/카메라(TPP·FPP)/사격/피격/루팅/인벤토리 최소, 테스트 박스 맵 | 1인 플레이로 파밍→교전→사망 사이클이 돌고 테스트 통과, 60fps |
| M1.5 | 에셋 도입 | 플레이어 캐릭터·기본 애니메이션, 무기 4종 모델, 테스트 맵용 PBR 머티리얼·HDRI, 핵심 효과음(총성·발소리·피격·재장전). 구역 D 소품 제외 | ① 룩 확인 장면 스크린샷을 사용자가 승인 ② 모든 에셋이 ASSET_LEDGER 기록·검증 통과 ③ 테스트 통과 ④ mac 빌드 성능이 PERF_BUDGET 내 |
| M2 | 구역 D(공장) | 첫 실제 구역 제작, 봇 AI(서버측), 엘리베이터 투입 | D에서 봇 N명과 한 판 완주, 예산 내 |
| M3 | 봉쇄 시스템 | 존 상태머신, 방사능 데미지, 열쇠/단일 출구/힌트, 폭격, 칩 보관함 | 한 구역에서 warning→closed 전 과정 자동 테스트 통과 |
| M4 | 구역 A + 구역 간 이동 | 산악 구역, 엘리베이터 구역 이동, 랜덤 폐쇄 순서·랜덤 최종 구역 | 2구역 풀 매치(봇) 완주, 최종 구역 랜덤성 테스트 |
| M5 | 싱글 완성판 | 솔로/팀(봇 팀원), 칩 부활, UI/메뉴/설정, 사운드 전반, 나머지 구역 순차(B,C,E,F,코어), 차량(옵션) | 릴리스 후보 빌드, 에셋 대장 100% 완비 |
| M6 | 멀티 전환 | Fish-Net 클라이언트 예측/지연 보상, 전용 서버 빌드, VPS/Edgegap 자체 호스팅 | 실제 2+ 클라이언트 매치 완주 |

## M0 세부 티켓 후보
1. unity.sh + 프로젝트 생성 + URP/패키지
2. 테스트 프레임워크 + CI 스크립트
3. BuildScript mac/win
4. 헤드리스 씬 생성 PoC (SceneBuilder)
5. 프레임타임/스크린샷 캡처 PoC
6. Fish-Net 호스트+클라 스모크
7. 에셋 임포트 파이프라인(KTX2, LOD) + ASSET_LEDGER 자동 검증 스크립트
8. PERF_BUDGET 측정·확정

## 우선순위 변경 규칙
M1~M5 순서는 바꾸지 않는다(M1.5는 사용자 지시로 M1과 M2 사이에 추가, ADR-035). 기능을 더 넣고 싶으면 ADR로 근거 + 예산 영향 기록.

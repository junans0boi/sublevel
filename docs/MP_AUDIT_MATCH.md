# 멀티플레이 한 매치 완주 검증 (#172, ADR-143)

`Tests/PlayMode/MatchEndToEndTests.cs` (Category Long, Explicit): 실제 로비 → World 매치 → 결과 → 로비까지 한 시나리오.
실행: `tools/unity.sh test playmode Game.Tests.MatchEndToEndTests` (약 3~4분, 매치 자체는 약 80초). 로그 `Logs/net-match/`, 사진 `MATCH_SHOTS`(기본 `Logs/matchshots`).
전용 서버판: `tools/unity.sh build server` 후 `Game.Tests.MatchDedicatedEndToEndTests` (아래 별도 절).

## 클라이언트별 수치 (한 번의 실행)

- 받은 데이터: 호스트 8.1, A 8.2, B 8.2, C 8.2 KiB/s (79초 평균, 봇 12 + 사람 4).
- 서버 거절/보정(`ServerGuard.CountFor`, `MoveGuard`): 전부 0. 단 시나리오가 단계 사이를 순간이동으로 옮기기 때문에 `MoveGuard.TrustTeleports`를 켰고, 사람 피해를 0.2배로 줄였다(우연히 죽지 않게).
- 프레임 시간(프로세스 전체, 단계별 평균/p99/최대 ms): 로비 2.9/4.0/494, 투입 7.7/38/331, 파밍 7.8/12/126, 교전 8.1/12/135, 차량 8.8/24/126, 봉쇄 7.7/13/118, 사망 8.2/14/125. (한 프로세스에 클라이언트 4 + 서버 + 화면 하나이므로 실제 클라이언트 값이 아니다.)

## 이 하네스로는 증명하지 못하는 것

- 원격 클라이언트마다의 UI: 한 프로세스에는 화면이 하나다. 원격 클라이언트의 화면은 `Combatant.LocalPlayer`를 바꿔 보여 주며, 각 클라이언트가 받은 방송(킬·상태·구역·보급)은 클라이언트별로 따로 세어 맞췄다. 원격 카메라는 "local"이 아니면 제자리에 멈춰 있어(이 프로세스 한정) 사진은 몸 뒤로 직접 놓고 찍었다. 같은 이유로 죽은 A·B의 결과 사진은 배경이 틀리고 글자만 맞다.
- 차량 사진은 서버·클라이언트 사본이 한 월드에 겹쳐 있어 머리가 여러 개 보인다. 실제 차량 화면은 전용 서버 + 별도 프로세스 클라이언트로 봐야 한다.
- 호스트가 아닌 사람의 기기, 다른 IP, 16명.

## 찾은 것

- **고침(ADR-143)**: `MoveGuard`가 의도적 순간이동의 위치 값을 `CmdTeleported`보다 먼저 받으면(지연 100 ms에서 신뢰 RPC와 비신뢰 위치의 순서가 뒤집힘) 정상 이동을 "치트"로 보고 되돌린다. 하네스의 `Teleport` 뒤에 `Move` 1건이 찍히고 몸이 423 m 되돌아간 것으로 확인했고, `MovementNetTests.LegitMovement…`의 간헐 실패("slow window 7 > 3": 되돌려진 러너를 서버가 계속 보정)의 뿌리로 본다.
- 열린 이슈: #180 월드 주차 차량 일부가 스로틀에 안 움직임(하네스 문제인지 미확정), #181 엘리베이터에서 같이 나오는 봇 몸이 겹침.

## 전용 서버(별도 프로세스) + 클라이언트 1 (`MatchDedicatedEndToEndTests`, 서버 `--bots 8 --max-players 4`)

로비 입장 → 시작 → 매치 접속 → 문 열림 → 길(내비메시)을 걸어 가장 가까운 총 줍기 → 나가기 → 서버가 빈 매치를 알아채 로비로 복귀까지 통과(250초).
- 서버 실프로세스에서도 집은 총은 탄창 0, 옆 탄약이 따로("[F] 9mm x30", 사진 `d02_looting.png`).
- 이 클라이언트가 받은 데이터 2.4 KiB/s(관심 영역으로 9명 중 4명만 받음), 서버 로그의 `[ServerGuard]` 거절 0건, 클라이언트 보정 0.
- 확인 못 함: 봇과의 교전(가장 가까운 봇이 200 m), 차량, 사망·결과 화면(사람 한 명으론 봇을 못 죽여 매치가 안 끝난다), 사람 둘 이상.

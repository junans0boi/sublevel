# 테스트 100개가 초록불인데 "너무 어색함" — 게임 제작기 #1 빈 폴더에서 총 쏘기까지

> 지난 화: 11월 12일 16시 24분, 문서 20개가 첫 커밋으로 올라갔다. KICKOFF를 받은 AI가 15분 뒤 처음 내린 판단은 "6.3 설치가 불완전해 보인다"였다.

그 판단에서부터 이야기가 시작된다. 이날 커밋은 27개, 시간은 7시간 반. 총은 생각보다 빨리 쐈다. 나머지 시간은 "총을 쏠 수 있다"와 "게임 같다" 사이의 거리를 재는 데 썼다.

![11월 12일 타임라인](img/ep01/diagram_timeline_1112.png)
*총은 1시간 반, 어색함은 6시간. 커밋·플레이 기록 시각으로 다시 그린 그림.*

## 첫 판단은 틀렸다

Unity 6.3 LTS를 쓰기로 해 놓고, AI는 "설치가 불완전해 보인다"고 했다. 나는 "설치하지 말고 지금 설치된 버전으로" 하라고 했다. 그래서 16시 39분, 이미 깔려 있던 6.6으로 프로젝트가 만들어졌다(ADR-018).

그런데 15분 뒤 정정 기록이 올라왔다. 6.3은 멀쩡히 다 깔려 있었다. 17시 07분, 6.3으로 프로젝트를 다시 만들었다(ADR-021). 네트워크 라이브러리 Fish-Net도 최신 4.7.4가 컴파일 에러를 내서 4.7.3으로 묶었다.

30분이 날아갔다. 이때 생긴 교훈이 나중에 문서에 이렇게 남았다. **"에이전트의 '설치 불완전' 보고를 사실 확인 없이 믿지 말 것."** AI가 자신 있게 말해도 확인은 해야 한다. 이 시리즈에서 이런 장면은 계속 돌아온다.

## 게이트부터 통과한다

본격적으로 만들기 전에 M0(기술 검증) 게이트부터 넘어야 했다. 안 되면 Godot로 갈아탄다. 0화에서 열어 둔 비상구다. 그래서 "이 기술로 정말 되나"를 재는 도구부터 만들었다.

- 프레임 시간 측정기(FrameStats): 게임이 얼마나 부드러운지 숫자로 잰다
- 서버 권위 테스트: 클라이언트가 값을 조작해도 서버 값이 안 바뀌는지 본다
- 에셋 대장 검사기: 라이선스 기록이 없는 에셋이 있으면 빌드가 실패한다
- 성능 예산 확정: 렌더 p99 10ms 이하, 드로우콜 2,500 이하, 삼각형 150만 이하(ADR-028)

17시 44분, M0 게이트 통과. 첫 커밋에서 1시간 20분. 비상구는 닫혔다.

## 회색 상자 방, 상대는 더미

17시 55분. 기본 도형으로 만든 테스트 방에서 이동, 3인칭/1인칭 카메라, 줍기, 사격, 재장전, 회복, 사망, 재시작이 다 됐다.

![회색 상자 방에서 더미를 쏘는 장면](img/ep01/testbox_dummy.png)
*회색 상자 방과 훈련용 더미. 11/16에 다시 찍은 화면이라 HUD는 이후 버전이다.*

상대는 봇이 아니었다. 제자리에 서서 보이면 쏘기만 하는 **훈련용 더미**였다(ADR-030). 봇은 로드맵상 M2다. "똑똑한 봇과 싸운다"는 게 이 게임을 만든 이유인데, 첫날의 상대는 과녁보다 조금 나은 인형이었다.

코드 리뷰에서 고친 게 하나 있다. 사격 시작점을 클라이언트가 보내던 걸 **서버가 아는 눈 위치**로 바꿨다. 클라이언트를 믿으면 벽 뒤에서 쏘는 핵이 가능하기 때문이다. 맥 빌드에서 평균 0.86ms, p99 3.73ms. 상자 방이니 빠른 게 당연하다.

## "에셋 언제 해?" — 계단을 하나 끼워 넣다

18시 17분쯤 처음 해 보고 남긴 말이다(PT-1).

> 일단 되긴 하는데 우리 에셋 도입 언제 해? 에셋 도입하고 M2 가는 게 나을 것 같다

회색 상자만 보고 있으니 뭘 만드는지 감이 안 왔던 것 같다. 그래서 M1과 M2 사이에 **M1.5 에셋 도입**이 끼어들었다(ADR-035). "M1~M5 순서는 바꾸지 않는다"고 적은 지 2시간 만에 로드맵이 처음 고쳐졌다. 순서를 바꾼 건 아니고 계단을 하나 끼워 넣은 거라고 하면… 할 말은 없다.

18시 41분에 룩 확인 장면이 나오고, 19시 08분에는 CC0 캐릭터에 애니메이션과 총 4종, 총성과 발소리까지 붙었다.

![CC0 캐릭터가 총을 든 모습](img/ep01/m15_weapons.png)
*"에셋 언제 해?" 1시간 뒤 붙은 첫 캐릭터와 총. 11/16에 다시 렌더한 화면이다.*

막힌 것도 있었다. 0원짜리 에셋인데 itch.io는 '구매' 절차를 거쳐야 했고, Mixamo는 계정이 필요했다. KICKOFF 규칙대로 AI는 결제와 계정 생성을 하지 않고 `blocked`를 남긴 채 다음으로 넘어갔다.

## 밤 11시, 처음 직접 해 본 게임

밤 11시, Windows 빌드를 직접 해 봤다. 그리고 쏟아냈다(PT-2). HUD가 텍스트뿐이다, 총알 나가는 느낌도 맞는 느낌도 없다, Q/E 기울이기가 배그와 다르다, Tab을 눌러도 인벤토리가 없다, 끄고 다시 켜면 아까 하던 판이 이어진다.

다시 읽어 보니 내 피드백의 자는 처음부터 **배그**였다. 기울이기도, 인벤토리도, 전부 "배그는 이런데"였다.

마지막 버그가 제일 황당했다. 원인은 **고정 포트 7770**이었다.

![고정 포트 7770 때문에 앞 판에 붙는 그림](img/ep01/diagram_port7770.png)
*끄고 켰는데 아까 그 판. ADR-044 기록으로 다시 그린 그림.*

앞서 켠 게임이 백그라운드에 살아 있으면 새 게임은 서버를 못 열고, 앞 게임의 판에 손님으로 붙었다. 매번 빈 포트를 찾아 쓰도록 고쳤다(ADR-044).

이 피드백으로 생긴 게 **M1.6 '게임 감각' 마일스톤**이다(ADR-043). 조준·이동 감각, 전투 피드백, 기본 UI. 기능이 아니라 **느낌**을 위한 마일스톤이 처음 생겼다. 하루에 두 번째로 끼워 넣은 계단이다.

## 23시 49분

23시 29분, 견착·조준, 기울이기, 이동 블렌드를 넣은 M1.6a가 올라왔다. 자동 테스트는 EditMode 66개, PlayMode 34개 전부 통과. 20분 뒤 다시 해 본 내 반응이다(PT-3).

> HUD 여전히 좌측 밑에 텍스트임
> Esc 누르면 그냥 꺼짐
> Q,E 기울이기는 배틀그라운드와 다르게 과함
> 너무 어색함

테스트 100개가 초록불인데 게임은 어색했다. 이날의 교훈은 나중에 이렇게 정리됐다. **"자동 테스트 통과 = 완료"가 아니다. "게임으로서 플레이 가능한가"를 따로 봐야 한다.** 테스트는 값이 바뀌었는지만 본다. 손맛은 못 본다.

그리고 하나 더 있었다. 이 피드백을 받아 다음 지시문을 쓰던 건 0화의 상담 채팅이었다. 그런데 상담 채팅은 코드도 빌드도 볼 수 없었다. 내가 보내는 사진과 글이 전부였다. "너무 어색함"을 직접 볼 수 없는 녀석이 그걸 고칠 지시문을 쓰고 있었다.

## 📚 이번 회차에 알아두면 좋은 용어

### 서버 권위 (Server Authority)
**한 줄 정의:** 맞았나, 몇 대미지인가, 총알이 몇 발 남았나 같은 중요한 결정은 **서버만** 내리고, 클라이언트(내 PC)는 결과를 받아 보여 주기만 하는 방식.

**우리 게임에서는:** 싱글플레이도 한 프로세스 안에 서버와 클라이언트를 같이 띄워(호스트) 돌린다(ADR-029). 첫날 이게 진짜 지켜지는지 테스트부터 만들었다. 클라이언트가 값을 999로 바꾸려 해도 서버 값 7이 그대로인지 본다.

`Assets/_Project/Tests/PlayMode/NetSmokeTests.cs`
```csharp
try { c.GetComponent<SmokeNetObject>().Counter.Value = 999; }
// ...
Assert.AreEqual(7, s.GetComponent<SmokeNetObject>().Counter.Value, "server value must be unchanged");
```

**왜 중요한가:** 클라이언트를 믿으면 누구든 자기 PC를 조작해 무적이 될 수 있다. 나중에 멀티를 할 거라면 첫날부터 이 구조여야 한다.

### 헤드리스 / 배치모드 (Headless / batchmode)
**한 줄 정의:** 프로그램을 **화면(창) 없이** 명령어로만 실행하는 것.

**우리 게임에서는:** AI가 Unity 에디터를 클릭할 수 없으니 프로젝트 생성·테스트·빌드를 전부 명령줄로 한다. 그 래퍼가 `tools/unity.sh`다.

```bash
mac) "$UNITY_PATH" -batchmode -nographics -quit -projectPath "$ROOT" -buildTarget StandaloneOSX -executeMethod BuildScript.BuildMac -logFile Logs/build-mac.log ;;
```

**왜 중요한가:** 사람 손 없이 반복할 수 있어야 AI가 혼자 "고치고 → 테스트하고 → 빌드"를 계속 돌릴 수 있다.

### p99 프레임 시간 (99th percentile frame time)
**한 줄 정의:** 프레임 100개를 느린 순으로 줄 세웠을 때 **가장 느린 1개 근처**의 시간. 평균은 좋아도 가끔 '뚝' 끊기는 걸 잡아낸다.

**우리 게임에서는:** `Assets/_Project/Scripts/Core/FrameStats.cs`가 앞쪽 워밍업 프레임을 버리고 정렬해서 계산한다. 성능 예산의 핵심 기준이 "렌더 p99 10ms 이하"다.

```csharp
Array.Sort(sorted);
float avg = (float)(sum / n);
int p99Index = Math.Min(n - 1, (int)Math.Ceiling(n * 0.99) - 1);
```

**왜 중요한가:** 플레이어가 느끼는 건 평균이 아니라 끊김이다. 평균 2ms여도 가끔 66ms가 튀면 "렉 걸린다"고 느낀다.

### 포트 (Port)
**한 줄 정의:** 한 컴퓨터 안에서 프로그램들이 통신할 때 쓰는 **문 번호**. 같은 번호의 문은 한 프로그램만 열 수 있다.

**우리 게임에서는:** 고정 포트 7770을 쓰다가 "재실행하면 이어지는" 버그가 났다. 지금은 원하는 포트가 막혀 있으면 운영체제에게 빈 번호를 받아 쓴다.

`Assets/_Project/Scripts/Net/MatchDirector.cs`
```csharp
public static ushort FreePort(ushort preferred)
{
    if (CanBind(preferred, out _)) return preferred;
    if (CanBind(0, out ushort assigned)) return assigned;
```

**왜 중요한가:** 네트워크 게임은 싱글플레이라도 내부적으로 서버를 연다. 문 번호가 겹치면 엉뚱한 판에 들어가는, 원인을 찾기 어려운 버그가 생긴다.

## 로그인한 브라우저를 넘기다

아침에 로그인했다. 그리고 그 브라우저를 AI가 쓰게 허락했다(ADR-165). 조건은 분명히 걸었다. 내가 **항목마다 승인한 무료 에셋만** 받는다. 결제, 비밀번호는 손대지 않는다. 계정은 원래 '절대 하지 않는 일' 목록에 있었다. 그 규칙에 처음으로 예외를 낸 날이다.

08:56, 첫 결과가 나왔다. Mixamo 소총 동작을 우리 캐릭터 뼈대에 맞게 **미리 구워서** 쓰는 우회로다(ADR-166). 우리 뼈대를 Unity가 사람으로 인식하지 못한다는 이유였다. 이 우회로는 반나절 뒤에 버려진다.

## "서브 세션이 뒤죽박죽이다"

17:12, 총괄 역할인 master 세션이 브리프를 쓰고 서브 세션들을 풀었다. 여러 세션이 **한 폴더**에서 동시에 일했다. 금방 엉켰다. "남이 Unity를 돌리는 중에는 코드를 컴파일되는 상태로만 둔다" 같은 규칙이 필요할 만큼 서로 발을 밟았다. 저녁에 나는 이렇게 판단했다.

> 서브 세션이 뒤죽박죽이다

19:15, 방식을 바꿨다. 일을 **트랙 10개**로 나눴다. 맵·재질·총기·차량·캐릭터·애니메이션·오염·봇/네트워크·UI·사운드. 트랙마다 자기 폴더와 자기 브랜치, 자기 결정 번호 대역(맵 204~209, 재질 210~214…)을 줬다. 끝나면 master가 하나씩 main에 합친다. 상세 수치의 원본은 정의서 하나. 이게 이날 생긴 틀이다.

틀을 세웠다고 사고가 없진 않았다.

- 아침의 굽기 우회로: 인식 실패는 다른 모델 이야기였다. Mixamo 캐릭터는 Humanoid로 잘 읽혔다(ADR-180·187). 반나절 만에 폐기.
- 대역을 나눴는데도 ADR-193이 두 줄 생겼다(22:12 정리).
- 총기 트랙 커밋이 캐릭터 설정 파일(.meta)을 지웠고, 애니메이션 브랜치는 충돌 표시(`<<<<<<<`)를 그대로 커밋했다.
- 봇/네트워크 트랙이 되감기 상한을 0.25→0.30초로 올렸다가 되돌렸다. 35m 빗나감의 원인은 상한이 아니라 중간의 장애물이었다(ADR-243).
- 게임이 자꾸 밤으로 시작했다. 시간대 기본값이 '무작위'라 네 판 중 한 판꼴로 밤이었다(ADR-210).

## 📚 이번 회차에 알아두면 좋은 용어

### 프로토타입 / 목업 (Prototype / Mockup)
**한 줄 정의:** 진짜 제품을 만들기 전에, 생김새나 흐름만 빠르게 흉내 낸 시제품.

**우리 게임에서는** 맵 시안이 `docs/research/map_options/*.html`(A·B·C·D·C2, 오염 시뮬레이션 `pollution_sim.html`), UI 시안이 `docs/research/ui_mockups/*.html`이다. 버튼을 누르면 화면이 넘어가는 클릭 목업(`proto.html`)도 있다. 브라우저로 열면 바로 보인다.

**왜 중요한가** 고르는 비용이 확 준다. Unity에서 틀리면 몇 시간, HTML에서 틀리면 몇 분이다. 단, 이날 로비처럼 **목업을 그대로 복사하면** 프로토타입이 아니라 그림이 된다.

### 절차적 생성과 시드 (Procedural Generation & Seed)
**한 줄 정의:** 사람이 하나하나 배치하는 대신 규칙과 난수로 코드가 콘텐츠를 만드는 방식. 시드는 그 난수의 출발값이다.

**우리 게임에서는** `Assets/_Project/Scripts/Core/World/IslandGenerator.cs`와 `IslandTerrain.cs`가 섬의 지형·마을·도로를 계산한다. 난수는 정수 해시로 만든다. 같은 좌표, 같은 시드면 언제나 같은 값이다. `IslandTerrain.cs`

```csharp
static double Hash(int ix, int iy, int s)
{
    unchecked
    {
        uint h = (uint)ix * 374761393u ^ (uint)iy * 668265263u ^ (uint)s * 1274126177u;
        h = (h ^ (h >> 13)) * 1274126177u;
        return (h ^ (h >> 16)) / 4294967296.0;
    }
}
```

**왜 중요한가** 같은 시드면 같은 섬이 나온다. 그래서 피드백("따닥따닥")을 받고 규칙만 고쳐 다시 뽑으면 섬 전체가 한 번에 바뀐다. 버그가 나도 같은 섬에서 재현할 수 있다.

### Humanoid 리그와 리타게팅 (Humanoid Rig & Retargeting)
**한 줄 정의:** 리그는 캐릭터의 뼈대다. Unity의 Humanoid는 뼈대를 '머리·팔·다리' 같은 표준 사람 구조로 읽어서, 한 캐릭터의 동작을 다른 캐릭터에 옮겨 쓰게(리타게팅) 해 준다.

**우리 게임에서는** `Assets/_Project/Editor/CharacterAnimClips.cs`가 Mixamo 동작 파일을 Humanoid로 다시 불러오고, 기준 캐릭터의 아바타를 복사해 쓴다(현재 코드).

```csharp
var imp = (ModelImporter)AssetImporter.GetAtPath(path);
imp.animationType = ModelImporterAnimationType.Human;
if (avatar != null) { imp.avatarSetup = ModelImporterAvatarSetup.CopyFromOther; imp.sourceAvatar = avatar; }
else imp.avatarSetup = ModelImporterAvatarSetup.CreateFromThisModel;
```

**왜 중요한가** 캐릭터가 15종이어도 걷기·장전 동작은 한 벌이면 된다. 아침의 '굽기' 우회로가 반나절 만에 버려진 이유도 이거다.

### Git LFS (Large File Storage)
**한 줄 정의:** 이미지·3D 모델·소리 같은 큰 파일을 git 밖 별도 저장소에 두고, 저장소에는 작은 '포인터'만 남기는 확장 기능.

**우리 게임에서는** `.gitattributes`에 어떤 파일을 LFS로 보낼지 적는다. 트랙 10개로 쪼개던 19:24~19:26에 커밋 두 개(`67ea34d8`, `7ffc9bf7`)가 그동안 그냥 들어가 있던 이미지·HDR 파일을 LFS로 옮겼다.

```
*.png filter=lfs diff=lfs merge=lfs -text
*.fbx filter=lfs diff=lfs merge=lfs -text
*.wav filter=lfs diff=lfs merge=lfs -text
```

**왜 중요한가** 큰 파일을 그냥 git에 넣으면 고칠 때마다 저장소가 통째로 무거워진다. 작업 폴더를 10개 만드는 날에는 더 그렇다.

> 지난 화: 실서버에서 안 열리던 문은 Mac과 Linux의 소수점 차이 때문이었다. 밤에 다시 해 본 r5.1은 "달리는데 느린 조깅 같다"였고, 조준경은 섬 전체에 열 개 남짓이었다. 그리고 r5.2를 해 본 내 피드백이 쏟아지기 시작했다.

11월 20일 0시 59분. 첫 커밋들이 그 피드백의 답이었다. 1시 1분, 달리기가 조깅 클립을 통째로 쓰게 바뀌었다. 1시 11분, 섬에 배율 조준경이 다시 깔렸다.

이날 커밋은 121개다. 밤 9시 12분에 끝났다. 지금까지 가장 바쁜 하루였다. 다시 읽어 보니 대부분이 내가 툭툭 던진 말에서 나왔다. 말 한 줄이 ADR(결정 기록)이 되고, 커밋이 되고, 저녁엔 버전 번호가 됐다.

## 오전 10시 48분, 판이 끝나지 않는다

이 시각의 커밋은 코드가 아니라 결정이었다(ADR-484).

#5에서 고른 오염 시스템은 지역 전체가 한꺼번에 오염 대상이 됐다. 안쪽으로 좁혀 오는 압박이 없었다. 마지막 지역에 대해선 내가 이렇게 적었다.

> "탈출만 막힐 뿐 존버하면 안 끝난다"

그래서 이렇게 바꿨다.

- 닫히는 지역 5개는 판이 시작될 때 **가스 상승** 아니면 **폭격**을 받는다(3:2 무작위).
- 가스는 가장 낮은 땅부터 차오른다. 폭격의 30%는 살아 있는 사람 근처로 떨어진다. 버티기 방지다.
- 최종 지역은 수렴 지점에서 먼 곳부터 잠기고, **25분에 전부 잠긴다.** 판 길이의 상한이다.
- 마지막 1팀이 남으면 바로 승리.

"탈출 승강기" 안도 나왔다. 그런데 결국 다 죽여야 지킬 수 있으니 의미가 없었다. 엘리베이터로 시작하는 게임인데, 엘리베이터로 끝내는 안은 버렸다.

봇도 규칙을 따라 바뀌었다. 가스나 폭격이 확정되기 **전에** 지역을 빠져나간다(ADR-533). 똑똑한 봇과 싸우려고 시작한 게임이니, 봇이 규칙을 먼저 알아야 했다.

## 📚 이번 회차에 알아두면 좋은 용어

### 버전 번호와 프로토콜 버전 (Versioning / Protocol Version)
**한 줄 정의:** 게임에 붙이는 `0.3.0` 같은 번호, 그리고 클라이언트와 서버가 "우리 같은 말을 쓰나?"를 확인하는 숫자.

**우리 게임에서는** `ProjectSettings`의 `bundleVersion` 하나만 원본으로 쓴다(ADR-535). 접속할 때는 `버전/프로토콜`(예: `0.3.0/8`)을 비교해서 다르면 로비가 거절한다. `Assets/_Project/Scripts/Net/LobbyNet.cs`:

```csharp
public const int Protocol = 8; // the island race hall's laps ... (긴 변경 이력 주석 생략)
// Both sides must agree on this to play together. Tests may change an instance's copy.
public static string CurrentVersion => Application.version + "/" + Protocol;
```

**왜 중요한가** 메시지 형식이 다른 클라이언트가 서버에 붙으면 이상하게 깨진다. "프로토콜을 올리면 버전도 올린다"는 규칙 때문에 이날 0.2.0과 0.3.0이 같은 날 나왔다.

### 드로우콜과 오클루전 컬링 (Draw Call / Occlusion Culling)
**한 줄 정의:** 드로우콜은 CPU가 GPU에게 보내는 "이거 그려" 명령 한 번. 오클루전 컬링은 벽 뒤에 가려 안 보이는 물체를 아예 안 그리는 기법.

**우리 게임에서는** 마을 위에만 영역을 깔고 미리 계산(베이크)해 둔다(ADR-547). `Assets/_Project/Editor/WorldBuilder.cs`:

```csharp
StaticOcclusionCulling.smallestOccluder = 4f;
StaticOcclusionCulling.smallestHole = 0.3f;
StaticOcclusionCulling.backfaceThreshold = 100f;
bool ok = StaticOcclusionCulling.Compute();
```

**왜 중요한가** 이 게임은 그리는 비용이 해상도보다 드로우콜 수를 따라갔다. 안 보이는 실내를 안 그리는 것만으로 마을 구도 드로우콜이 크게 줄었다.

### LOD (Level of Detail)
**한 줄 정의:** 멀리 있는 물체를 덜 자세한 모델로 바꿔 그리는 기법.

**우리 게임에서는** Unity의 Mesh LOD를 총 모델 28개에 켰다(ADR-541). 모델 설정 파일 한 줄이다. `Assets/_Project/Art/Weapons/Roster/Wpn05_Sentinel.fbx.meta`:

```yaml
    generateMeshLods: 1
```

**왜 중요한가** 80명이 각자 총을 들면 총만으로 삼각형이 많이 쌓인다. 거리에 따라 단순해져야 80인 판에서 버틴다.

### 내비메시와 복셀 (NavMesh / Voxel)
**한 줄 정의:** 내비메시는 봇이 "걸을 수 있는 바닥"을 표시한 지도. 복셀은 그 지도를 만들 때 세상을 잘게 쪼개는 작은 정육면체로, 작을수록 정밀하지만 용량이 커진다.

**우리 게임에서는** 복셀을 봇 반지름의 1/3에서 1/2로 키웠다(ADR-544). `Assets/_Project/Editor/WorldBuilder.cs`:

```csharp
// Half the radius (ADR-544, #426): radius / 3 baked 31.9 MiB, over the 30 MB budget; radius / 2 bakes 21.2 MiB ...
const float NavVoxelSize = AgentRadius / 2f;
```

**왜 중요한가** 정밀도와 용량은 맞바꾸는 관계다. 건물 411채 중 410채에서 봇이 여전히 현관까지 나올 수 있는지 재 보고 나서 바꿨다.

# 자고 일어나니 멀티플레이가 돼 있었다 — 게임 제작기 #3 커밋 118개의 하루 (11/14)

> 지난 화: 임시 상자 차가 진짜 차와 오토바이로 바뀐 밤. 연료와 차량 피해는 반쯤 만든 채 자정을 넘겼고, 지역 사이를 오가는 엘리베이터(#76)는 "나중에"로 미뤄 둔 채였다. 그리고 나는 맥북을 바꾸기로 했다.

## 반쯤 만든 코드를 들고 이사

자정 직전, 돌던 에이전트를 직접 멈췄다. 00:04에 반쯤 만든 연료·차량 피해 코드가 `wip:` 커밋으로 올라갔다. 1분 뒤에는 `RESUME_ON_NEW_MAC.md`가 올라갔다. "어디까지 했고, 새 맥에서는 뭘 해야 하는지"를 적은 문서다.

새 맥의 첫 세션은 그 문서를 읽고 바로 이어서 일했다. 사람이 이사할 때보다 짐 풀기가 빨랐다. 연료와 제리캔, 경적, 부위별 차량 체력, 타이어 펑크, 연기 → 불 → 폭발까지 새벽에 다 마감됐다.

그리고 전날 미뤄 둔 그 숙제가 나왔다.

## 미뤘던 엘리베이터가 움직이다 (01:56~03:08)

#2에서 엘리베이터는 '처음 들어가는 문'이었다. 이날 새벽에는 **지역과 지역을 잇는 길**이 됐다(ADR-076·079). 승강장에서 F를 누르면 문이 닫히고, 카가 내려가고, 바닥에서 다른 카로 갈아타고, 다시 올라와 문이 열린다. 규칙도 붙었다. 안전하거나 '경고' 상태인 지역에서만 운행하고, 목적지는 안전한 지역만 고를 수 있다. 봉쇄가 다가오는 지역에서는 엘리베이터가 탈출구가 된다는 뜻이다.

![습지 승강장에서 막 내린 장면](img/ep03/elevator76.png)
*02:13 캡처. 미뤄 뒀던 지역 간 엘리베이터가 새벽 2시에 움직이기 시작했다. 왼쪽 위에 지역마다 '안전/봉쇄 1:00' 상태가 뜬다.*

봇도 탔다. 봉쇄 예고가 뜬 지역의 봇은 엘리베이터를 타고 빠져나간다. 봇이 처음으로 "도망칠 줄 아는" 순간이었다.

솔직히 나는 엘리베이터에 아직 확신이 없다. 낙하산만큼 재밌을까. 그런데 이날 새벽, 엘리베이터는 투입 수단에서 이동 수단으로 한 칸 더 커졌다. 내가 의심하는 동안에도 엘리베이터는 계속 일을 늘려 가고 있었다.

물론 바로 매끄럽진 않았다.

![엘리베이터 안에서 팔을 벌리고 있다](img/ep03/elevator79.png)
*02:24 캡처. 엘리베이터를 타는 동안 캐릭터가 팔을 벌리고 있다.*

카를 갈아타는 동안 캐릭터는 통로 바닥에서 기다린다. 그런데 발밑 검사에 아무것도 안 걸려서 **"공중에 떠 있다"고 착각했고, 점프 자세가 나왔다.** 엘리베이터에 탄 동안은 공중이 아니라고 알려 주는 것으로 고쳤다(ADR-080).

## "나무 막대기" (04시)

새벽 4시쯤 직접 해 봤다. 그때 남긴 말이 그대로 기록에 있다.

> 한 손으로 총, 상체 고정, 다리만 바쁨, 나무 막대기

원인은 캐릭터 파일에 든 총 동작이 전부 **한 손 권총 자세**였던 것. 소총도 한 손으로 들고 몸통은 굳어 있었다. 에이전트는 새 동작 파일을 들이지 않고 **코드로 두 손 자세를 만들었다**(ADR-083). 평소엔 총구를 내리고 있다가, 조준하면 0.15초 만에 어깨에 붙인다.

04:45에는 `PUBG_GAP_V2.md`가 나왔다. 배그와 우리 게임의 차이를 "완료/부분/없음"으로 나눈 표다. 내가 "어색하다"고 한 걸 AI는 숫자로 옮겼다. 정조준 탄퍼짐은 배그 비율로(ADR-089), 이동 속도는 배그 표 그대로 달리기 4.7, 질주 6.3 m/s로(ADR-095). 손맛을 숫자로 바꾸는 방식이다. 이게 맞는 번역인지는 해 봐야 안다.

이 세션은 토큰이 떨어져 중간에 멈췄다.

## "묻지 말고 멀티까지" (05:48)

그래서 새벽 6시 전에 지시를 남겼다(`RESUME_ON_NEW_MAC.md` §9).

첫 커밋의 ROADMAP에는 "M1~M5 순서는 바꾸지 않는다, 멀티는 M6"이라고 적혀 있었다. 그 문장이 이 한 줄로 사실상 끝났다. 이틀 만이었다.

그 뒤 두 시간 동안 싱글 기능이 20개 남짓 들어갔다. 탄도 낙차, 조준경 영점, 수류탄 쿠킹, 섬광탄, 열고 닫는 문, 키 설정 33개, 봇 감사표(`BOT_AUDIT.md`)와 봇 난이도. 그리고 07:39, 날씨가 들어왔다.

## 멀티를 위한 틀부터

에이전트는 07:49에 먼저 조사를 했다. 우리가 쓰는 네트워크 라이브러리(Fish-Net) 무료판에서 **"쏜 사람 화면 기준으로 시간을 되감아 판정하는 기능"은 유료판 전용**이었다. 돈은 안 쓴다는 규칙이 있으니 직접 만들기로 했다(ADR-121).

그다음 만든 건 기능이 아니라 **시험장**이었다. 한 프로세스 안에 호스트와 손님 여럿을 띄우고, **지연 100ms·패킷 손실 2%를 일부러 넣는** 테스트 틀(ADR-123). 이 틀 위에서 나머지가 차례로 붙었다.

- 방 만들기, IP로 참가, 준비, 봇 수 정하기 (08:15)
- 화면 없이 도는 전용 서버 (08:51)
- 멀리 있는 건 안 보내기: 클라이언트당 14.7 → 8.5 KB/s (12:04, ADR-135)
- 지연 보상 사격 (18:04)
- 서버 검증: 말이 안 되는 이동·연사는 거절 (18:13, ADR-142)

마지막 시험에서 하나가 걸렸다. 차에서 내리면 캐릭터가 문 옆으로 순간이동한다. 그런데 "순간이동했다"는 알림이 위치보다 늦게 도착해서, 서버가 그 이동을 **핵으로 보고 되돌렸다.** 0.45초 기다려 주는 것으로 고쳤다(ADR-143).

## 📚 이번 회차에 알아두면 좋은 용어

### 지연 보상 (Lag Compensation)
**한 줄 정의:** 내 화면에서 맞혔으면 서버도 인정해 주도록, 서버가 **잠깐 과거로 시간을 되감아** 판정하는 기법.

**우리 게임에서는** 서버가 모든 캐릭터의 위치를 약 1초 분량 기록해 둔다. 총을 쏘면 "쏜 사람이 보고 있던 시각"으로 다른 캐릭터를 옮겨 놓고 판정한 뒤 되돌린다. 되감기에는 상한이 있다(이날 0.25초, 지금은 0.30초). `Assets/_Project/Scripts/Net/LagCompensation.cs`

```csharp
var rec = c.GetComponent<PositionRecorder>();
if (rec == null || !rec.History.TryAt(at, out float x, out float y, out float z)) continue;
var now = c.transform.position;
if (DistanceToSegment(now, from, to) > reach) continue;
var then = new Vector3(x, y, z);
if ((then - now).sqrMagnitude < MovedEpsilon * MovedEpsilon) continue;
Moved.Add((c, now, then));
c.transform.position = then;
```

**왜 중요한가** 인터넷에는 늘 지연이 있다. 이게 없으면 "분명 맞혔는데 안 맞았다"가 계속 생기고, 핑이 높은 사람은 게임을 못 한다.

### 관심 영역 (Interest Management)
**한 줄 정의:** 서버가 모든 정보를 모두에게 보내지 않고, **그 사람 근처의 것만** 골라 보내는 방법.

**우리 게임에서는** 캐릭터 300m, 아이템 100m, 투척물 200m 안의 것만 보낸다. 팀원은 거리와 상관없이 보낸다. 경계에서 깜빡이지 않게, 이미 보이던 것은 조금 더 멀리까지 유지한다. `Assets/_Project/Scripts/Core/Interest.cs`

```csharp
public static bool Observes(InterestRules rules, InterestKind kind, bool seen, in InterestObserver observer, bool teamMember)
{
    if (!rules.Enabled || kind == InterestKind.Always) return true;
    if (!observer.HasBody) return false;
    if (teamMember) return true;
    if (observer.Dead && kind != InterestKind.Loot) return true;
    return Within(rules, kind, seen, observer.NearestMeters);
}
```

**왜 중요한가** 넓은 맵에서 전부 보내면 네트워크가 못 버틴다. 덤으로, 안 받은 정보는 핵 프로그램도 볼 수 없다.

### 전용 서버 (Dedicated Server)
**한 줄 정의:** 플레이하는 사람 없이 **서버 역할만 하는 프로그램.** 화면도 없다.

**우리 게임에서는** 서버용 프로그램을 따로 만들지 않았다. 같은 게임 빌드를 `--dedicated` 옵션으로 화면 없이 실행하면 서버가 된다. `Assets/_Project/Scripts/Core/ServerArgs.cs`

```csharp
//   --dedicated            run as a dedicated server (no window, no local player)
//   --port N               lobby port, default 7770 (the match listens on N+1)
//   --bots N               bots that fill the match; default: fill up to the usual size beside the people
```

**왜 중요한가** 한 플레이어 컴퓨터가 호스트면, 그 사람이 나가면 판이 깨지고 그 사람만 핑이 0이다. 전용 서버는 모두에게 공평하다.

### 서버 검증 (Server-side Validation)
**한 줄 정의:** "클라이언트를 믿지 마라." 플레이어 컴퓨터가 보낸 값을 **서버가 다시 확인**하고, 말이 안 되면 거절하거나 되돌린다.

**우리 게임에서는** 이동은 내 화면에 먼저 반영하고(그래야 안 굼뜨다), 서버가 "그 시간에 그만큼 갈 수 있나?"를 검사한다. 질주 속도에 여유를 더한 것보다 멀리 갔으면 되돌린다. `Assets/_Project/Scripts/Core/MoveReconcile.cs`

```csharp
public static bool Implausible(float dx, float dy, float dz, float seconds, LocomotionParams l, out float excess)
{
    seconds = Math.Max(0f, seconds);
    float flat = (float)Math.Sqrt(dx * dx + dz * dz);
    float flatAllowed = MaxHorizontalSpeed(l) * seconds + SlackMeters;
    float upAllowed = MaxVerticalSpeed * seconds + SlackMeters;
    excess = Math.Max(Math.Max(0f, flat - flatAllowed), Math.Max(0f, Math.Abs(dy) - upAllowed));
    return excess > 0f;
}
```

**왜 중요한가** 검증이 없으면 순간이동 핵을 막을 수 없다. 대신 이날처럼 **정상적인 순간이동(차에서 내리기)까지 핵으로 볼 수 있다.** 그래서 검증에는 늘 '여유'가 필요하다.

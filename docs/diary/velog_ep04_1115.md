## 3/30의 범인은 시체였다

그 전에 조준 측정에서 이상한 숫자가 나와 있었다. **20m 앞 가슴에 서서 정조준으로 30발을 쏘면 3발만 맞는다.** 배그라면 서서 정조준하면 거의 다 맞아야 한다. 총이 고장 난 줄 알았다.

19:10, 다시 재 봤다. 조준 오차는 정상이었다. 진짜 원인은 **측정 쪽**에 있었다. 3발째에 더미가 죽었고, **쓰러진 더미 몸이 다음 총알을 막고 있었다.** 한 발마다 더미 체력을 다시 채우는 테스트로 바꾸자 30발 중 30발.

총은 멀쩡했다. 다행인데 좀 허탈했다. 그래서 규칙 하나를 얻었다. **숫자가 이상하면 총보다 자부터 의심하라.**

수영도 코드로 자세를 만들고 바다 가장자리까지 헤엄칠 수 있게 넓혔다(ADR-145). 결과 화면은 배그처럼 큰 순위와 수치 타일로 바꾸고 **이동 거리** 칸을 넣었다(ADR-146). 이 두 결정의 근거 칸에는 "사용자 플레이 피드백(배그 비교)"이라고 적혀 있다.

## 📚 이번 회차에 알아두면 좋은 용어

### 회귀 테스트 (Regression Test)
**한 줄 정의:** 한 번 고친 버그나 확인한 동작이 **나중에 다시 망가지지 않았는지** 계속 자동으로 확인하는 테스트.

**우리 게임에서는** "서서 정조준하면 20m 30발이 다 맞는다"를 테스트로 박아 두었다. 진짜 키 입력 경로로 쏘고, 한 발마다 더미 체력을 채운다. 주석에 이번 사건이 남아 있다. `Assets/_Project/Tests/PlayMode/AdsAccuracyPlayTests.cs`

```csharp
input.Frame.FirePressed = input.Frame.FireHeld = true;
yield return new WaitForSeconds(0.7f); // the view settles back, the next shot is a fresh one
dummy.ServerHeal(100f); // 3 hits would kill it, and a dead body stops the next bullet (that was the earlier 3/30)
Assert.AreEqual(AimMode.Sights, me.AimMode, "still in the sights");
```

**왜 중요한가** AI가 하루에 커밋을 수십 개 하면 누가 뭘 망가뜨렸는지 사람이 다 볼 수 없다. 회귀 테스트가 대신 지켜본다. 단, 이번처럼 **테스트 자체가 틀릴 수도 있다.**

### 역운동학 (Inverse Kinematics, IK)
**한 줄 정의:** "손이 여기 있어야 한다"는 **끝점을 먼저 정하고**, 어깨·팔꿈치 각도를 거꾸로 계산하는 방법.

**우리 게임에서는** 1인칭 팔을 코드로 만들고, 어깨에서 총 손잡이까지 위팔·아래팔 두 마디로 뻗게 했다. 두 길이와 거리를 알면 팔꿈치 위치가 삼각형으로 나온다. `Assets/_Project/Scripts/Gameplay/FirstPersonArms.cs`

```csharp
var line = target - shoulder;
float d = Mathf.Clamp(line.magnitude, Mathf.Abs(a - b) + 1e-3f, a + b - 1e-3f);
var dir = line.sqrMagnitude > 1e-8f ? line.normalized : Vector3.forward;
float x = (a * a - b * b + d * d) / (2f * d);
float h = Mathf.Sqrt(Mathf.Max(0f, a * a - x * x));
var perp = Vector3.ProjectOnPlane(pole, dir);
perp = perp.sqrMagnitude > 1e-8f ? perp.normalized : Vector3.up;
wrist = shoulder + dir * d;
elbow = shoulder + dir * x + perp * h;
```

**왜 중요한가** 총마다 손잡이 위치가 다르다. IK가 있으면 총이 바뀌어도 손이 알아서 손잡이를 찾아간다.

### 절차적 애니메이션 (Procedural Animation)
**한 줄 정의:** 미리 만든 동작 파일 대신, **코드가 매 프레임 수식으로 관절을 움직이는** 방식.

**우리 게임에서는** 수영 동작 파일이 없어서 코드로 만들었다. 다리는 사인 곡선으로 차고, 왼발과 오른발은 반 박자 어긋난다. `Assets/_Project/Scripts/Core/Swim.cs`

```csharp
// Flutter kick: a leg's thigh turn (degrees about the right axis) for a kick phase 0..1; the other leg opposite.
public static float KickThigh(float phase, int side, SwimRules rules) =>
    rules.KickDeg * (float)Math.Sin((phase + 0.5f * side) * 2.0 * Math.PI);
```

**왜 중요한가** 라이선스 걱정 없는 동작 파일이 적을 때, 코드는 언제든 쓸 수 있다. 대신 "로봇 같다"는 느낌이 나기 쉽다. 이날 밤 남은 "애니메이션이 어색함"이 바로 그 대가다.

### 레이캐스트 (Raycast)
**한 줄 정의:** 한 점에서 한 방향으로 **보이지 않는 광선을 쏴서 무엇에 부딪히는지** 알아내는 기능.

**우리 게임에서는** 주차된 차가 떨어지며 바퀴가 땅속에 묻히면, 바퀴가 땅을 영영 못 찾고 차가 멈췄다. 출발점이 이미 땅 안이라 아무것도 안 맞았기 때문이다. 그래서 바퀴 위 0.5m에서 아래로 다시 쏘게 했다(20:52). `Assets/_Project/Scripts/Net/Vehicle.cs`

```csharp
const float Lift = 0.5f;
var up = transform.up;
int rays = Physics.RaycastNonAlloc(AnchorWorld(i) + up * Lift, -up, WheelHits, Lift + r.WheelRadius, Physics.DefaultRaycastLayers, QueryTriggerInteraction.Ignore);
```

**왜 중요한가** 게임 속 "닿았나?"의 대부분이 레이캐스트로 답해진다. 어디서 쏘느냐 하나만 틀려도 차가 안 움직인다.

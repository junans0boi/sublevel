## 정정 (3D 로비, ADR-247)
- 로비 배경은 시안 SVG 그림이 아니라 **실제 3D**: `Editor/LobbyStageBuilder`가 `WorldBuilder.Elevators`와 같은 조립법·같은 `WorldMaterials`(Door·PaintedMetal·RustyMetal·ShaftLamp·DoorStripe·Concrete)로 승강기 칸+역 벽+홀 바닥을 MainMenu 씬에 만든다(칸은 4인이 서도록 게임보다 넓힘 4.4 m, 모든 치수·재질 코드가 게임 것을 따름). 캐릭터는 `Roster_*.prefab` 15종, 저총 자세+소총, 숨쉬기 흔들림.
- 모든 비로비 화면은 같은 3D를 뒤에 두고 시안의 dim(.84)을 적용. 시안 배경 PNG·장면 SVG는 삭제(아이콘 8종만 유지, ledger U-0001 갱신).
- **PlayerAppearance**(모델 id·변형·장비 단계) 저장·읽기·파티원 필드·테스트 7건, API 문서 `ui_APPEARANCE_API.md`. 로비 내 자리 = 저장된 값, 외형 탭에서 15종 전부 선택 가능(가짜 잠금 없음, 시안의 24칸 중 9칸은 그리지 않음 — 시안은 "기본 12 + 해금 12"이지만 실제 로스터가 15종이라), 변형은 모델의 `CharacterDef.Variants`, 헬멧·조끼·배낭 단계 선택, 고르는 즉시 3D 캐릭터에 반영·저장, 취소는 진입 때 값 복원, 마우스 드래그로 회전.
- 시안과 다른 점: 3D 배경이라 시안의 평면 장면과 모양이 다르다(요청에 따른 의도). 승강장 타일은 3D 위 오버레이(바닥 표식), 파티장·준비 배지는 캐릭터 발 위치를 투영해 따라간다. 빈 자리는 점선 타일+초대 버튼.
- **인게임 외형 일치 검증은 못 함**: 스폰이 `PlayerAppearanceStore.Load()`를 읽는 코드는 애니 트랙 몫(API 문서). 로비 쪽 값은 `docs/bible/img/ui/lobby_look.txt`(저장된 값 MixamoSwatGuy 변형 1)와 로비 캡처로 확인.
- PERF: 로비 프레임 시간 테스트는 배치 모드에서 0.2 ms로 나와 실제 렌더 비용을 못 믿는다(미측정으로 기록). 모델 15종이 MainMenu 씬에 참조돼 메모리는 병합 뒤 플레이어 빌드로 재측정해야 한다.
- 되돌려야 할 것: `WorldMaterials.Prepare`가 `Prefabs/World/Materials`를 건드려 커밋에서 제외함.

## 후속 (뒷벽·썸네일·설정·훈련장·결과 슬롯·PERF, 2026-11-17)
- **뒷벽**: 게임 콘크리트(`WorldMaterials`)는 파이프라인의 버텍스 단위 추가 광원 때문에 큰 면에서 대각선 경계, 타일로 쪼개면 체크 얼룩이 생겨 쓰지 못함 → 자체 제작 노이즈 텍스처(URP Lit) + 줄눈. 파란 얼룩(림 라이트가 벽 뒤에서 비춤)·키 라이트 좌우 반대 수정.
- **로스터 썸네일**: 에디터 빌더(`LobbyStageBuilder.RenderRosterThumbs`)가 로비 조명으로 15장 렌더 → `Resources/Ui/RosterThumbs/<ModelId>.png`.
- **설정**: 기존 `SettingsScreen` 기능·API(SelectTab/Row/Apply/Back) 유지, 겉모양을 3D 로비 위로: 시안 상단 층 표시기 바 + dim, 패널 #10151C 82%·1px 테두리·장식 괄호 제거, 8px 마진. **시안의 4탭(키 설정을 조작에 병합)은 미적용**(5탭 유지: 키 설정 행 구조 변경은 회귀 위험), 컨트롤은 시안의 선택 상자형이 아니라 기존 화살표형.
- **훈련장 진입**: 시안 카드 3장 중 게임에 실체가 있는 2장(사격장·봇 연습 매치)만 그리고, 기본 조작 안내 카드·8단계 진행 패널(가짜 데이터)은 그리지 않음. 시작하기가 선택에 따라 `StartTraining`/`StartGame`.
- **결과 화면**: 시안은 팀표·오염·열쇠·칩 요약이 필요해 병합 뒤로 미룸. 필요한 값은 `docs/tracks/ui_RESULT_SLOT.md`.
- **PERF(로비, 1920×1080, 4인+UI, 에디터 PlayMode 카메라→RT+1픽셀 리드백, 160프레임)**: 평균 8.74 ms, **p99 15.15 ms**, 드로우콜 202, 배치 198, 삼각형 115,920. PERF_BUDGET A(렌더 p99 ≤ 10 ms; 최소 14 ms): **불합격**(15.2 ms), 드로우콜(≤2500)·삼각형(≤1.5M)은 합격. 프레임 평균 8.74 ms는 B(17 ms) 합격이나 C의 8.3 ms를 약간 넘음. 원인 후보: 후처리(블룸·비네트), 추가 광원 5개+스포트 2개, 스키닝 캐릭터 4명, 1080p 투명 UI. 최적화는 아직 안 함(필요하면 로비 후처리 단순화·림 스포트 제거로 재측정).

## 결함 최소 수정(iter7)과 PERF 정리 (2026-11-17)
- **룩 고정, 최소 수정만**: 벽의 가로 줄 2개(줄눈) 제거, 왼쪽 위 흰 빛줄기(키 라이트를 왼쪽으로 옮긴 부작용) → 키 라이트를 iter4 위치(화면 오른쪽)로 복귀, 이름 카드가 발을 덮음 → 카메라 목표 y를 0.10 m 낮춰 인물이 약 35 px 올라가고 카드를 48 px 높이로 줄여 y 872로 내림(발이 카드 위에 보임), 썸네일은 팔짱 포즈+더 가까운 상체 크롭. 파란 얼룩은 iter5에서 제거됨 유지. 전/후 `iter7_lobby_squad_1920x1080_before.png`(=iter5) → `iter7_*_after.png`.
- **PERF 재측정(로비 1920×1080, 4인+UI, 에디터 PlayMode, 카메라→RT, 설정별 100프레임)** — 측정법: sync(렌더+1픽셀 리드백, GPU 완료 포함)와 submit(렌더 호출만) 병행. 결과 파일 `docs/bible/img/ui/lobby_perf*.txt`.
  - 같은 빌드 반복 3회 기준선: **sync 평균 7.3~8.1 ms, p99 10.6~11.5 ms**(이전 보고의 15.15 ms는 다른 Unity가 동시에 돌던 때의 잡음 값으로 보인다), submit 평균 0.8~1.0 ms(CPU는 병목 아님), 드로우콜 230, 배치 226, 삼각형 약 11.6만.
  - 기여표(평균 ms 기준, 한 번에 하나 끔): 캐릭터 4명 **-3.4~-4.1**, 추가 라이트 5개 전부 -0.1~-1.1(p99 -2.0~-2.6), UI 오버레이 -0.4~-1.6, 후처리 -0.8~-1.1, 그림자 거리 0, MSAA -0.2~-1.9. **같은 설정의 p99가 반복마다 ±3 ms 흔들리고, 라이트 하나를 끄면 오히려 p99가 올라가는 경우가 있어(추가 라이트 단독 끔 시 +1.6~+6.9 ms) p99는 이 환경에서 신뢰 낮음**(동시에 도는 Unity·GPU 경합). 평균은 안정적.
  - 시도: 로비 캐릭터 Mesh LOD를 한 단계 낮춤(`LobbyStage.MeshLodBias=1`) → 삼각형 11.6만→7.6만, 평균 7.3~7.6 ms이나 **p99는 개선 없음**(10.97~11.1 ms)이고 같은 빌드 두 번의 프레임 차이가 잡음 수준(평균 절대차 11.2)이라 룩 회귀를 수치로 보장할 수 없어 **채택하지 않음(0으로 되돌림)**.
  - 판정: 평균 ≤ 8.3 ms(C)는 **충족**(7.3~8.1), p99 ≤ 10 ms(A)는 **미충족(10.6~11.5, 약 0.6~1.5 ms 남음)**. 단 잡음 때문에 확정 불가: 다른 Unity가 없는 상태에서 600프레임 이상으로 재측정해야 한다. 안전한 후속 최적화 후보(룩 변화 거의 없음): 후처리 단순화(볼륨 -1.0 ms 평균)·로비에서 MSAA 낮춤(URP 에셋은 공용이라 이 트랙 소유 밖 → master 판단).
